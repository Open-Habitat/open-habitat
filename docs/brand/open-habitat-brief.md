# Open Habitat — brand identity brief

Open Habitat needs a recognizable identity for its browser interface. The product name is chosen; the visual identity is to be designed and selected with Jari.

## Product and audience

Open Habitat brings a browser interface to AI agents running in each person's
own Linux account. People open their workspaces and use native agent histories
also available through SSH and tmux. Files, credentials and processes stay with
the native tools; Linux accounts separate users. The first agent is Pi on a
single Linux host. The Finnish-language interface is designed for desktop and
phone, with light and dark themes.

The audience is people using coding agents in developer workspaces and small
teams sharing a Linux host. The identity should help them recognize the product
in a browser tab and navigation, and feel calm, technical and approachable.

“Habitat” refers to agents working in their native environment. “Open”
describes the project’s openness, not support for every agent or access path.
The readable name is **Open Habitat**.

## Creative direction

An open doorway is one possible expression of entering a native environment.
Use it as inspiration. Recommend the form that best fits
the product and remains recognizable at small sizes, and compare it with a
viable alternative. Explain the choice through actual-size examples. A symbol
should work alongside the name and independently where space is limited.

The UI has neutral surfaces and a muted teal accent: `#2b7f8c` in the light
theme and `#4fa6b4` in the dark theme. Typical backgrounds are `#ffffff` and
`#f6f7f8`, or `#1b1f23` and `#14171a`. These are integration context; the
logo's palette is part of the design. Keep the identity distinct from agent
brands and operational status indicators. Meta's Habitat simulation project
is a known neighboring name to consider when judging visual similarity.

Explore short, removable taglines in English and natural Finnish. “Your agents,
in their native habitat” and “The browser door to native agents” are starting
ideas. The name and small symbol should work on their own.

## Applications and handoff

Show the recommended identity and alternative in the places where people will
encounter them:

- A large web logo and a compact header version, with desktop and phone examples.
- A standalone navigation mark and favicons at 16×16 and 32×32 pixels.
- App icons at 192×192 and 512×512 for possible launcher use.
- Light, dark and monochrome versions, including reversed artwork.

Check small marks at actual pixel size, and header layouts at narrow widths and
200% browser zoom. Show grayscale legibility and report measured contrast for
text and functional graphics in their intended UI uses against the applicable
accessibility requirements. These examples should make it possible to judge
recognition, readability and fit with the interface before choosing an identity.

Deliver editable vector masters and optimized, static web SVGs, with transparent
PNG exports and favicon files. For custom lettering, include outlined artwork
and editable source with font names and usage and redistribution rights. Web
assets should be self-contained. Provide a concise guide to variant filenames,
colors, minimum sizes, clear space and appropriate uses, including mistakes
that would harm legibility or recognition.
