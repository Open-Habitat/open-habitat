## Walking-skeleton boundary

The first implementation slice proves seams rather than breadth: two principals; one explicit tenant; durable sessions/events and minimal audit; one lifecycle adapter; one independently addressed harness adapter; one two-ended host-connectivity adapter; one low-risk mediated tool plus one denied or approval-required operation; disconnect/reconnect; ambiguous lifecycle and input reconciliation; capture-gap handling; and completed-session inspection after runtime/workspace cleanup.

The detailed acceptance and failure-injection list is canonical in [reference architecture v0 §14](https://github.com/maintainer/native-agent-host/blob/2292047fc1a59efb3a22e9373eba46b8599e74ca/issues/native-agent-host-architecture/reference-architecture-v0.md#14-walking-skeleton-boundary).

## Adoption proofs

- **Alder:** the dossier establishes one-Unix-user trust, separate Pi/Taskfleet/Git/tmux stores and authorities, ambient tool power, and one live worker correlation. The fit-gap must carry forward the unavailable attached-seat path, second-principal behavior, interrupted lifecycle tests, post-merge cleanup, complete correlation, deletion, and confinement evidence.
- **Northwind:** the dossier establishes personal-clone onboarding, worktrees as the documented parallel-session boundary, shared host/Git collision surfaces, local gates, credential classes, and a narrow CI hand-off. The fit-gap still needs representative developer interviews or observed workflows, live Claude/session behavior, safe concurrency evidence, centralization appetite, and operational acceptance.
- **Native Creator:** the dossier establishes a local single-user TUI, unrestricted local tools, BCF artifacts, MCP capabilities, and an API-key-to-organization cloud/Moodle seam. The fit-gap must preserve uncertainty about the inaccessible fork/package, deployed correspondence, end-user/school identity, runtime history, and live provider/Moodle behavior.
- **Creator web:** the dossier establishes an organization-scoped browser platform, roles, shared workspaces, durable drafts/jobs, private SSE/application runtime, pooled application isolation, and an absent Moodle path. The fit-gap must account for source/deployment drift and the lack of authenticated synthetic, restore, provider, and Moodle observations.

The next bounded evidence step is to run the **minimal custom API baseline** against the frozen fixture and produce the three adoption fit-gaps (Alder, Northwind, and combined Acme with implementation divergence retained). The fixture's own tests validate only deterministic plumbing, safety guards, and evidence integrity; they are not B1–B8 or candidate results.
