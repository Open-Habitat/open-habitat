# ADR 0013: One readable format for service logs

**Status:** Accepted by Jari on 2026-10-05. Request records and a gateway request ID
are decided in [ADR 0022](adr-0022-request-records.md).

The gateway, root broker and per-user daemons currently write uneven diagnostics to stderr. Some records are structured JSON, others are startup text, and useful failures are not recorded at all. An operator needs to know where to look and be able to understand and connect the records that already describe the same operation.

Each service writes its own diagnostic messages to stderr; systemd collects them in that service's journal on Linux. Host-owned diagnostic messages use a consistent JSONL shape: time, level, component, event and outcome, with a classified reason where relevant and useful context such as the verified user, operation and existing attempt or request ID **when available**. The logging guide shows real examples and the command to find each service's records. Record relevant failures and consequential actions across the gateway, broker and daemon, not routine noise. Do not copy credentials, URLs with tokens, conversation text, tool output or native command stderr into these records. Logs are evidence of what was observed, not a source of authorization or native state.

No new correlation protocol or browser support-reference system is required just for logging. Existing IDs appear in the records that know them; an absent ID is not fabricated or treated as a join key. A separate need for end-to-end tracing can be decided after real operational experience. The implementation should reuse Go's standard logging facilities where they suffice, rather than create a buffering, aggregation or storage subsystem. Log delivery failures must not change the result of an operation. Normal systemd journal access, retention and disk controls are installation concerns; Fleetrepo documents and verifies the concrete test guest, including that one mapped user cannot read another's diagnostics. Per-event retention classes and bespoke reader ACLs are not part of this decision.
