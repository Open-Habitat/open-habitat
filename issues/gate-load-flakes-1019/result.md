# Load-sensitive gate repair

## Investigation

All testing uses synthetic homes and credentials, same-UID browser hosts and fake providers; no live server or deployment is involved.

- Warm return: reproduced the original five-second quiescence failure with 12 repetitions of both reported browser cases over eight workers, concurrently with `go test -race ./...`. 23/24 passed; warm return failed once. Log: `/var/tmp/oh-gate-load-baseline-browser.log`. Trace extracted to `/var/tmp/oh-trace.MuqIXmos`. The setup measured immediately after creating two controllers, while native catalog invalidations were still arriving. A 300 ms quiet interval cannot establish that those events are over; polling also competes with recurring process/spinoff reads. An attempted event-driven quiet wait still hung or let later creation snapshots enter the measurement under heavier load (traces `/var/tmp/oh-trace.AYD4llmU`, diagnostic logs below). The final setup creates both controllers, opens a fresh page from the current snapshot/event cursor, then warms both retained controllers through in-page navigation. No creation or native write occurs in this measurement page. This removes the timing-based quiescence wait altogether. The measured route assertions remain unchanged.
- Restart inventory: the poll accepts two interrupted records but the assertions previously performed another full `/proc` census. That later census can correctly be uncertain under same-UID process churn. Keep the observation that passed the poll instead; writer-present denial and the record-content assertions remain. The original inventory failure did not recur locally in 40 baseline repetitions. A subsequent full Go suite under browser/repetition load failed in the same test at provider request 7 (`/var/tmp/oh-gate-load-go-suite-2.log`). Its wake path waited only for idle plus a 200 ms sleep, not completed history publication. Replace that sleep with a newer wake-turn generation plus the existing quiescence condition. Also publish the fake Taskfleet inventory by rename: its real concurrent Python reader must never see `os.WriteFile`'s truncated JSON. The missing-provider timeout alone does not establish which of these fixture races fired.
- Archive: the shared test helper retries a definite `control_uncertain` refusal by reloading the *current* URL. The UI has already navigated optimistically to the workspace, so reload cannot restore the conversation header. Rediscovery must return to the captured original view. A stale-token response in the existing terminal journey deterministically exercises this refusal against the real daemon. A further loaded run reproduced a disabled action whose reason was `Prosessin tilaa ei voitu vahvistaa.`; the helper had recognized only archive-state uncertainty. Both unknown-read reasons permit read-only rediscovery, not an unchecked write. Unknown or unobserved write outcomes remain non-retryable.
- Worktree archive: reproduced the original 409 in 1/12 parallel lab repetitions (four workers); extracted trace `/var/tmp/oh-trace.fxrwdQ3u` confirms `control_uncertain`, not writer conflict. Use the same bounded helper. On a workspace card it reloads the same view rather than inserting another browser-history entry, preserving the later Back assertion.

## Decisions for later review

No product or authority changes are intended. Keep conservative native-writer uncertainty and explicit write refusal semantics; repair the tests rather than weakening the native census or adding product retries.

## Focused self-review

The review checked that archive retries require a positively observed 409 `control_uncertain` or a known unknown-read state and a fresh enabled action, never an ambiguous write, busy denial or writer conflict; workspace retries preserve browser history; the fresh measurement page retains one SSE and warms both controllers before the Back journey; warm-route assertions still prohibit status/history/controlled recap reads and SSE reopening; and restart record-content assertions still use a positive census. The wake wait must see a newer turn generation as well as quiescence, so the old turn's idle state cannot satisfy it.
