# Bounded broker refusal diagnostics

The gateway now records `broker_operation` and a fixed `broker_reason` on a rejected OAuth callback, sharing only the existing server-generated attempt ID with the start event. The browser response, token handoff, session issuance and Unix socket/peer authority are unchanged. The CLI adapter translates validated broker failure enums into fixed typed errors; transport and state-unavailable remain transient on later authorization checks. The root writer additionally logs a fixed pre-reservation guard stage for host availability errors or exhaustion, without an identity or attempt ID.

Gateway-only classification is **not enough** to diagnose the pilot.4 refusal: a `name_collision` reply can mean an unsafe candidate, occupied name, UID/GID occupancy or path residue, while `drift` can cover NSS, parent ownership/ACL, path probing or unit checks. All can leave an empty ledger. Root-local pre-reservation stages separate errors by guard family, but `no_available_binding` still conflates occupied names, existing paths and UID pool exhaustion. The root log and gateway attempt cannot be joined by an identifier: the protocol deliberately does not carry an attempt ID. A bounded operator-held time window is suggestive, not proof of correlation. Transport failures include socket admission, framing and malformed wire replies; those are not independently distinguishable here without changing the client transport error contract. Nothing here proves which pilot branch failed, nor does synthetic testing establish live host state.

Security review (independent `claude-fable-5-1` finder and `gpt-6-astra` verifier): confirmed misleading root exhaustion stage, collapsed pre-reservation guard errors, misleading invalid-request classification and incomplete numeric-leak test; corrected all four.
