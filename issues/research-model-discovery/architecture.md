# Proposal: Pi-native model selection with honest availability

**Status:** proposal for Jari, not an ADR. No change to gateway, provisioning or the Unix-user boundary.

## Discovery and ownership

The mapped-UID daemon asks *that user's pinned Pi runtime* for its authenticated chat-model catalog and global default. It reads through native Pi APIs; gateway only proxies the result to the authenticated browser over that user's verified socket. The `openai-codex` picker is a list of **candidates**. Authentication and catalog membership do not prove that a subscription permits inference. The daemon never reads another user's home, exports credentials, calls the Codex backend with Pi's OAuth token, or maintains an independent model/entitlement registry. Existing implementation: [`pi_models_linux.go`](../../internal/daemon/pi_models_linux.go), [`pi_models_helper.mjs`](../../internal/daemon/pi_models_helper.mjs).

For new Pi versions, revalidate the helper's API and pinned manifest before changing its version guard. If online catalog refresh is wanted, invoke Pi's native targeted refresh on deliberate picker open or explicit refresh, within a bounded timeout; return the last native cached Pi snapshot on a network failure *with a stale-catalog indication*. Never have gateway perform account discovery or store a copy. If native Pi provides no trustworthy refresh timestamp or last-error signal, say “catalog may be outdated” rather than inventing freshness. The current offline helper can remain a safe baseline.

## Choice and proof

Continue to use Pi `SettingsManager.setDefaultModelAndProvider` for the **global default for new sessions**. Existing sessions have native model-change and thinking-level entries: a new default must not retroactively switch a live conversation. Offer a separate deliberate in-session model change only if Pi's native RPC/session semantics can safely apply it, otherwise require a new session. Thinking selection is separate: Pi `defaultThinkingLevel` / per-model `modelThinkingLevels` live in native settings for startup; `/thinking` writes the current session. Clamp to the selected model's supported reasoning levels instead of assuming `xhigh` works everywhere. Native session history, not browser state, is the authority after reconnect. [Pi models](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/models.md), [settings](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/settings.md).

A successful actual user turn is the strongest available proof. An optional **explicit, one-model-at-a-time verify action** may send a trivial prompt via Pi as the mapped UID, with `--no-session --no-tools --no-extensions --no-skills --no-context-files --print` or equivalent pinned native API; bounded deadline, no parallel sweep, and visible warning that a call consumes usage. Disable any project-specific context and be mindful of home-level Pi hooks when testing the exact release. Do not change the default just because a probe succeeds. If the user's genuine send fails with the provider's unsupported-model error, emit only a fixed safe error code (existing controller classification); retain the input/uncertain-send rules and guide to selecting a different model in a **new** session. Do not replay automatically. A successful test establishes only “worked at verification time,” not a durable entitlement. No host-side per-model positive/negative cache. [Existing recovery](../../docs/architecture/conversations.md), [incident](../pi-not-answering-live/result.md).

## Browser contract sketch

Evolve [`pi-models.schema.json`](../../contracts/v1/pi-models.schema.json) from `{default_provider, default_model, models:[{id,name}]}` by versioning the response and adding `source: "pi_catalog"`, `availability: "unverified"` per model, and an optional catalog freshness status (`native_cached`, `native_refreshed`, `unknown`). This is **presentation metadata only**, not an entitlement estimate. If per-model supported thinking levels are reliably available from Pi, expose those as optional native metadata. The write contract [`pi-model-update.schema.json`](../../contracts/v1/pi-model-update.schema.json) continues to select a Pi-native global default; require provider-qualified IDs if more than one provider is exposed to avoid collisions. Keep `Cache-Control: no-store`, existing bounds and secret-safe error classification. A verify endpoint, if built, should take one provider-qualified ID, use the existing mapped-daemon auth boundary and return a bounded result (`answered`, `unsupported`, `auth_required`, `rate_limited`, `unavailable`), not raw provider output or tokens. Surface actual usage and a clear opt-in; implement only after deciding verification is worth the cost.

## Failure and staleness

Unavailable Pi, expired auth, offline catalog, and a provider rejecting inference are distinct states. For no credential, ask for native Pi login. If catalog refresh fails, show Pi's own cached candidates as uncertain and preserve the currently saved native default, even if no longer listed; do not replace it silently. If Pi's model runtime fails entirely, show native unavailable rather than guessing from a shared catalog. An old session whose model is now unsupported stays readable; next message requires explicit action/new session. Do not promise that a once-verified model will work tomorrow: plan/workspace rights, retirement, quotas and network change. Let native Pi refresh/staleness machinery own its persisted catalog; browser requests are not a polling job. [Pi catalog behavior](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/models.md), [Codex model retirement](https://developers.openai.com/codex/models.md).

## Decision needed before implementation

Agree that the picker presents **candidates**, with optional paid/on-quota explicit verification, rather than pretending a complete entitlement list is available through Pi. Reconsider a Codex-specific `model/list` integration only if Codex becomes a separately hosted native agent; it has its own configuration and credentials and is not Pi's authority.
