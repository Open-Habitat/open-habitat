# Atlassian sign-in fails at once: the integrations profile's pi wrapper runs Pi's library entry, not its CLI

## Description

Jari 9.11.2026 on Birch (pilot.24): Settings › Data for agents › Atlassian →
start failed at once. Daemon journal: `integration_login provider=atlassian
outcome=failed phase=login reason=tool_failed` 303 ms after the POST.

## Cause

`/opt/open-habitat/integrations.json` maps `pi` to the integrations profile's
wrapper `profiles/integrations/bin/pi`, generated by
`scripts/integrations-runtime-build.py:34`:

    exec "$core/bin/node" "$core/node_modules/@earendil-works/pi-coding-agent/dist/index.js" "$@"

`dist/index.js` is the package's library `main`, not its CLI (`bin.pi` is
`dist/bundle/cli.js`). Running the wrapper with any arguments prints nothing
and exits 0 (`pi --version` → empty), so the RPC child closes its output and
`startPiOAuth` ends with `ToolFailed`. The same command with
`dist/bundle/cli.js` works on Birch: `--version` → 1.3.0, and `/mcp` over RPC
reports `open_habitat_atlassian: needs sign-in`.
`scripts/test-integrations-runtime.py:88` asserts the wrong path. The
Atlassian worker's fixtures used a fake Pi, so nothing exercised the real
wrapper. The wrapper's comment says it serves `pi mcp add/remove`, so any
other caller of this `pi` (Microsoft's MCP registration) is affected the same
way; check and record.

Second observation from the same probe: Pi warns *"MCP tools are only
reachable from the codemode or tool_search tool, but neither is active; they
cannot be called."* Verify that the daemon-owned agent Pi session (not the
login child) actually has a way to call the Atlassian MCP tools after
sign-in; if not, that is part of this fix.

## Acceptance Criteria

- [ ] The wrapper runs Pi's CLI (`dist/bundle/cli.js` or the package's `bin.pi`, resolved rather than hard-coded if practical); the runtime test asserts it and runs `--version` on the built profile.
- [ ] A test against the real built integrations profile (not a fake Pi) starts the RPC login child and sees Pi's `/mcp` response.
- [ ] The agent's own Pi session can call the Atlassian MCP tools after sign-in (verified with the real runtime, fixture server acceptable for the remote).
- [ ] Integrations runtime profile rebuilt for both architectures for the next release.
