# Result: one browser journal stream

The catalog and controlled conversation no longer own separate EventSource connections. `ConversationJournal` validates SSE schema, kind, cursor, event ID and sequence; keeps one global cursor per tab; handles replay, 401/409 probe, restart, snapshot recovery and per-agent tail truncation; and routes opened windows through `ConversationStore`. Unopened conversations advance the cursor without allocating windows. Background status events refresh cached statuses; active events reach the conversation's status/continuation owner. A fresh snapshot cannot rewind the cursor or publish a pre-invalidation page as current. Old text stays readable with a stale state while reconciliation runs. The daemon retains up to 1024 replay events or 16 MiB, whichever first, while preserving the 1 MiB per-frame invalidation limit.

## Review and design

This is an asynchronous integration spanning stream transport, store reconciliation and daemon replay, without changing identity or server authority. One focused final-diff review was chosen rather than a panel. The finder reported seven reproducible bugs (older snapshot seeding, duplicate EventSource timer, early entry skipping tail, invalidation status, duplicated queued status, stranded queued events, and routine ten-minute offline flash). Each was checked against source, repaired and covered by targeted tests where needed; GPT-6 Astra independently refuted both high-risk findings against the repaired code and ran 35 focused tests. No residual issue met the filing bar and no accepted design departure was needed. Review/assessment scratch is under ignored `history/`. The optional model-performance corpus write failed on the known alder SSH-to-self issue (`@assess-models-alder-self-ssh`); it did not affect code review or validation.

The first full clean gate stopped at an old browser test waiting for a stream to reopen on conversation creation. That expectation was replaced with a one-connection assertion. Subsequent focused runs found a confirmed-missing-history race, a synthetic 409 test that expected a stale snapshot to reopen a stream, and a cold-open race that read history before status proof; all were corrected. The clean gate on `9aac861` passed all 116 host browser cases but exposed a test race where automatic journal recovery removed a manual retry button. The next run passed 116/116 host cases but exposed three lab assumptions about per-conversation streams: newly created agents needed a refreshed snapshot to seed their live window, and forced synthetic 409/gap tests tried to reopen from an unchanged cursor. The production seeding was fixed, those tests now assert safe recovery, and the final gate passed. Intermediate clean gates were cancelled when new actionable evidence required code changes.
