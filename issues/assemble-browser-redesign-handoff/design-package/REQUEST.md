# Whole browser experience redesign / Koko selainkokemuksen uudelleensuunnittelu

## Suomeksi

**Tehtävä.** Native Agent Host on suomenkielinen, ensisijaisesti työpöytäselaimessa käytettävä väylä Linux-palvelimen omiin työtiloihin ja natiiviin Pi-agenttiin. Käyttäjä kirjautuu, valitsee `~/src`-työtilan, lukee natiivihistoriaa, aloittaa tai jatkaa keskustelun ja seuraa työtä selaimen sulkemisen jälkeenkin. Git, Pi-historia ja tunnukset pysyvät natiiveissa työkaluissa; jokaisella ihmisellä on oma Unix-käyttäjä, eikä selain valitse tai päättele Linux-tunnusta. **Jari pitää nykyistä käyttöliittymää kokonaisuutena puutteellisena. Suunnittele koko selainpolku uudelleen johdonmukaisena järjestelmänä, älä vain korjaa pikseleitä.** Käytä kuvapareja nykytilan evidenssinä, älä hyväksyttynä visuaalisena tavoitteena. `docs/product.md`, `docs/ui.md` ja `design-system/production-v1.md` rajaavat sovitut tuotteeseen ja vuorovaikutukseen kuuluvat asiat; erottele nykyinen toteutus, sovittu tavoite ja oma ehdotuksesi.

**Käyttäjän polku ja ongelmat.** Työstä GitHub-ensikäynti (valinnainen repovalinta, Pi:n oma kirjautumisvaihe), paluu, työtilan avaus, vain luettava terminaalihistoria, uusi ja jatkettu keskustelu, lähetyskuittaus, kesken työn ohjaus ja jonotus, työkalut ja tuntematon sisältö, katkos/epävarma tulos, asetukset ja uloskirjautuminen. Jarin pilot.12-palaute (`TODO.md`, kohta testipalvelin): uloskirjautumisen keskeytys on liian neutraali, repovalinta vaati toisen painalluksen, ikkunan vaihto näytti tyhjän istunnon varmistusnäkymän, Pi-kirjautumisen ensimmäinen painallus näytti ensin virheen ennen koodia ja paluu oli hidas, uuden keskustelun aloitus tuntui oudolta. Nämä ovat pilotin raportteja, eivät kuvasarjan toistotodisteita; älä ehdota visuaalista ratkaisua toiminnallisen vian korvikkeeksi. Aamukatselmuksen kysymykset (`issues/overnight-ui-review/review.md`): ensikäytön painotus, paluun lupaus, työn/historian/valmiin vastauksen ero ja tumman teeman löydettävyys. Kierrosten auditit (`issues/decidedly-loud-station/audit.md`, `relatively-robust-flower/audit.md`, `unduly-grateful-slip/audit.md`, `extremely-impartial-spiders/audit.md`, `highly-fanatical-beam/audit.md`, `absurdly-fair-horse/audit.md`, `inordinately-zany-kick/audit.md`) kuvaavat mm. vanhaa luonnoksen katoamista, katkoksen peittämää historiaa, lukutilan liian raskasta kehystä ja metadatan ylikorostusta, kilpailevia tarkistuspainikkeita, paluun read-only-epäselvyyttä, ensikäytön painotusta sekä tuntemattoman sisällön raakaa JSON-esitystä. Useat näistä on sittemmin korjattu synteettisesti: älä kutsu niitä nykyisiksi vioiksi; arvioi jäljellä olevaa visuaalista laatua 21 uudemmasta `rendered-pages/`-parista. `chat-working` näyttää työnaikaista ohjausta, ei todista koko jonon elinkaarta. Tyhjä-, virhe- ja osittainen tila eivät kaikki ole tässä kuvasarjassa; suunnittele ne tuotteen sääntöjen mukaan, älä väitä niitä kuvatuksi.

**Avoimet asiat, ei päätöksiä.** `issues/decide-account-display/item.md`: varmennetun näyttönimen näyttäminen geneerisen “Oma tili” -tekstin sijaan ja yksi keskustelureitti ovat Jarin päätettävänä; älä ota kumpaakaan toteutettuna tai muuta identiteetin auktoriteettia. `issues/complete-conversation-ui/result.md`: rakenteinen `edit`-diffi odottaa todistettua natiivia tietoa; älä päättele diffiä vapaasta tekstistä. Näytä ehdotuksesi näille ehdollisina vaihtoehtoina. Älä lupaa yksittäisen jonorivin perumista, hiljaista komentojen uudelleenlähetystä, kirjoitusoikeutta terminaalihistoriaan tai suoritettavaa hostin HTML:ää. Hostin ja agentin teksti on epäluotettavaa; käsittele se inerttinä ja säilytä pitkän tuloksen valinta, kopiointi, fokus ja lukukohta. Katkos näyttää vanhentuneen sisällön vain samalle varmennetulle identiteetille; epäselvällä identiteetillä sulje näkyvyys turvallisesti. Säilytä todellinen tilatieto (loading, empty, stale, partial, unknown, rejected, accepted), väriä täydentävät tekstimerkit ja näppäimistö-/ruudunlukijakäyttö.

**Palauta.** (1) Offline avattavat, staattiset HTML/CSS-näkymät (ei kuvakollaaseja eikä toimivaa host-integraatiota) koko edellä kuvatulle polulle vaaleana ja tummana, 1440 px desktopina ja 390 px kapeana varianttina; huomioi zoom, pitkä suomi ja reduced motion. (2) Komponenttitason spesifikaatio, joka käyttää nykyisiä `web/src/components/`-nimiä sekä toteutuksen ja tilojen kartoitusta; merkitse uudet komponentit erikseen. (3) Käytä `design-system/tokens/`-tokeneita tai ehdota nimenomaisesti perustellut muutokset ja vaalea/tumma-arvot, älä luo piilotettua rinnakkaista asteikkoa. (4) Perustelu kullekin olennaiselle muutokselle: käyttäjän tarve, nykytilan havainto, vuorovaikutus, saavutettavuus ja toteutuksen vaatima mahdollinen sopimusmuutos. Kerro mitä kuvien ulkopuolisista tiloista päättelit ja mitkä asiat tarvitsevat Jarin tuoteratkaisun.

## In English

**Brief.** Native Agent Host is a Finnish, desktop-first browser front end to a person's Linux workspaces and native Pi sessions. Git repositories, credentials and session history remain in their native tools, also reachable over SSH/tmux. People have separate Unix accounts; the browser never chooses a Unix identity. Jari considers the current UI deficient as a whole: propose a coherent redesign of the entire browser journey, not pixel-level polish. Treat the 21 synthetic image/HTML pairs as evidence of current implementation, not approval; `docs/product.md`, `docs/ui.md` and `design-system/production-v1.md` describe agreed behavior. Clearly distinguish implemented behavior, target behavior and your proposal.

**Scope and evidence.** Design first GitHub sign-in, optional repo selection and separate Pi setup; returning user, workspace and read-only terminal history; new/resumed conversation, send receipts, working/steer/follow-up queues, grouped tools and unknown content; outage, uncertain send, empty/error/partial, account settings, theme and sign-out. `issues/overnight-ui-review/review.md` asks whether first-use hierarchy, return promises, reading versus working versus done, and theme discoverability are right. The seven selected audit reports show earlier draft loss, stale-history loss, heavy transcript chrome, metadata prominence, competing check actions, return-link ambiguity and raw unknown JSON; several were fixed after those audits. Evaluate the later captures rather than presenting fixed defects as current. Jari's pilot.12 reports in `TODO.md` describe neutral-looking logout cancellation, repo choice responding only on second click, a blank session-verification transition, delayed Pi code after an initial error and slow return, and odd new-chat start. These are live pilot observations, not reproduced by the synthetic images: interface suggestions do not replace functional fixes. `chat-working` shows a working state but does not prove full queue settlement. Some empty/partial/error screens are not in this set; design them from the agreed behavior and label them proposed.

**Boundaries and open decisions.** The verified account display name and unified conversation route in `issues/decide-account-display/item.md` are undecided: present conditional proposals, not a new authority model. A structured Pi edit diff is not proven by the current text history (`issues/complete-conversation-ui/result.md`); do not infer one from free text. Do not invent per-item queue cancellation, auto-retry uncertain writes, write access to terminal sessions, or executable agent/host HTML. Treat incoming text as untrusted. Keep draft, reading position and selected tool groups stable; preserve last confirmed content as stale only for the same confirmed identity, failing closed on ambiguous identity. Explicitly distinguish loading, empty, stale, unknown, partial, rejected and accepted. Keyboard and screen-reader behavior, contrast, 200% zoom, long Finnish names and reduced motion matter as much as color.

**Return deliverables.** Offline static HTML/CSS redesigned screens for the whole journey, light and dark, desktop and 390px; component-level specs mapped to existing `web/src/components/` names with any new components identified; use `design-system/tokens/` or explicitly propose justified token changes for both themes; rationale per substantive change covering user need, evidence, interactions, accessibility and any required contract decision. Label unpictured states and assumptions rather than treating synthetic captures as live-user verification.
