# Result

`@softeria/ms-365-mcp-server` raised from 0.170.1 to exactly 0.191.0 in
`runtime/profiles/integrations/package.json`, with the adapter's
`@azure/msal-node` raised from 5.6.0 to 7.2.3 in the same change. **The
integrations runtime must be rebuilt in the next release**; installed hosts
keep 0.170.1 until then.

Later upstream releases (0.191.1, 0.191.2, 0.192.0, 0.193.0) were out of
scope. 0.191.1 and 0.191.2 fix how the SDK v2 migration fills path parameters
whose names overlap. The synthetic write fixture and the tool calls exercised
here did not show that bug, but the next pin watch finding should take them.

## What changed and why

- **One MSAL.** The server now requires MSAL `^7.1.1`. With the adapter left
  on 5.6.0, npm nests a second MSAL under the server, and the adapter's
  `instanceof AuthError` no longer recognises the server's errors, so a refused
  grant read as `unreachable` (the regression the 0.190.5 research reproduced).
  Raising the root to 7.2.3 deduplicates the two. `scripts/test-integrations-runtime.py`
  now fails if a nested MSAL appears under the server again.
- **Lock.** Updated with script-disabled npm against the existing lock, not
  resolved from scratch. The MCP SDK v1 (`@modelcontextprotocol/sdk`) and its
  helpers (ajv, cors, jose, zod-to-json-schema and others) leave the closure.
  `@modelcontextprotocol/{server,core,node}` 2.x (Apache-2.0, already a licence
  family in the closure) come in, along with zod 4.6.7, msal-common 16.17.0
  and patch versions of hono and @hono/node-server. keytar is still the only
  package with an install script; the builder skips it and the daemon disables it.
- **Scope patch.** `ms-365-mcp-server-scopes.json` is raised to 0.191.0. All 15
  `from` field sets match the new `endpoints.json` exactly, so the `to`
  semantics are unchanged. The new `appScopes` fields only apply in upstream's
  `--app-mode`, which the product does not use.
- **Mail delete.** Upstream turned `delete-mail-message` into a move to
  Deleted Items (`POST …/move`) that returns the moved message. Deleting a
  message that is already in Deleted Items now leaves it there instead of
  purging it. The approval question in `microsoft-permission.mjs` now says the
  message moves to Poistetut and can be restored, and it has a test.
  The stronger `delete-mail-message-skip-deleted-items` is not offered.
- **Presets.** The mail/calendar/contacts presets gained
  `delete-mail-message-skip-deleted-items`, `list-rooms` and the six account
  tools, and their listing order changed. `microsoftOutlookTools` is not
  widened. `TestMicrosoftMCPToolsPinnedServer` now compares sets and names
  those reviewed exclusions in `microsoftExcludedOutlookTools`, so any further
  preset change still fails the test.
- **Account tools.** 0.170.1 registered `login`, `logout`, `verify-login`,
  `list-accounts`, `select-account` and `remove-account` in every stdio process
  whatever `--enabled-tools` said, and the daemon hid them from every area. 0.191.0
  respects `--enabled-tools`, so the server no longer lists them at all.
  The `msmcp.SignIn` filter stays as defence.
- **Refusals.** A tool call outside the configuration now returns `Tool X is
  not available in this server configuration: <reason>` instead of `Tool X not
  found`. The test's assertion follows that wording. The synthetic write
  fixture's fake server gained the `tools/call` handler that upstream's new
  denied-tool hook wraps.
- **Annotations.** `download-bytes-to-file` is no longer marked read-only.
  Approval is decided by tool name (`guardedTools`), not by annotation, so
  nothing changes here.
- A pre-existing defect in `TestMicrosoftSingleGrantNativeRuntime` was fixed:
  its verify-protocol probe used a bare address without the connection's tenant, so it
  returned before reaching the adapter on the previous pin as well. It now
  names a connection in the test tenant.

## What changes for agents

- The same Microsoft tools in the same areas. The relay
  (`open-habitat-mcp-relay microsoft`) and its stdio protocol are unchanged:
  the server still negotiates `2025-06-18` with newline-delimited JSON.
- Deleting a mail message always moves it to Deleted Items and returns its new
  id. The tool's own description now refers to a permanent-delete tool that
  is not offered. If an agent tries that tool, it gets the "not available in
  this server configuration" refusal.
- Refused tool calls state their reason, for example the missing scope for a
  write on a read-only files grant.
- Tool descriptions and hints are revised upstream (reply drafts, contact
  `$filter`, room lists, delta sync), and input schemas are generated by zod 4.
  The listing of the whole surface is about 5 % smaller.

## Checks

All on Linux arm64 (native) with Node 22.23.5 from the integrations lock:

- `scripts/build-profile-runtime.sh integrations NEW_PROFILE` passed, and so
  did `python3 scripts/test-integrations-runtime.py NEW_PROFILE CORE_RUNTIME`
  (npm closure, notices, modes, wrappers, scope patch, single MSAL).
- `microsoft-native.test.mjs` in the built payload passed: import, reload,
  rotation, refusal vs. outage, verify states and guest pins.
- A scratch migration check passed: a grant imported with the 0.170.1 / MSAL
  5.6.0 tree was verified (`ok`) and silently refreshed by the 0.191.0 / MSAL
  7.2.3 tree on the same encrypted store.
- With `OH_TEST_MICROSOFT_RUNTIME` and `OH_TEST_RCLONE` set to the built payload,
  `TestMicrosoftSingleGrantNativeRuntime` and `TestMicrosoftMCPToolsPinnedServer`
  passed. A baseline build from the previous commit showed that the verify-probe
  failure predated this change.
- `python3 scripts/test-profile-runtime-build.py` passed 16 tests.
- `node --test internal/daemon/pi-device-test/microsoft-permission.test.mjs` passed.
- `scripts/test-focused.sh --area go` passed for `./internal/msmcp`, `./internal/host` and
  `./internal/daemon/integrations`. In the integrations package,
  `TestTrelloCatalogAddsAnotherConnection` failed once under full-package
  load. It passed alone three times here and on the base commit. It is
  unrelated to Microsoft.
