# Title-language regression — result

The first title attempt saw only the first accepted user message. Before this fix, explicit regeneration also sent only the first and third messages, omitting the second entirely; the model prompt merely said “language of the conversation”. An English first prompt could therefore dominate a later Finnish exchange, and the model had no explicit rule for a mixed-language excerpt. The exact Pi history and provider response from the pilot.22 observation were not available, so this is the reproducible route to the observed symptom, not a claim to have recovered that particular model call.

The controller now retains a bounded latest accepted user message for regeneration. The third-turn refinement uses the third message, even if a fourth arrives while naming is in flight. A continued session without in-memory prompts reads the latest user message from its active native branch. The model instruction names the latest user's language rather than the UI language or the first message. Titles still go through the existing tool-free Pi call and `set_session_name` RPC; no title store, timing change, or altered failure behavior was introduced.

## Decisions for review

- Use the latest user message as the language cue when messages differ; keep the first message as bounded topic context. The first automatic attempt cannot predict a later language switch. The scheduled third-turn refinement and explicit regeneration can correct it.
- Do not add a language detector or a browser-language hint. Pi's model already reads the excerpt; giving it a precise rule preserves non-Finnish conversations without coupling title language to localization.
- On continuation, prefer the last user message in the active, readable native branch. If that read is unavailable, retain the existing first-prompt excerpt rather than making regeneration unavailable. Native name preconditions and failure preservation remain unchanged.
