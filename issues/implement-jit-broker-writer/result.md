# Root broker journal core result

Implemented an inert Linux `Writer.Handle` with an explicit injected `HostExecutor` and an explicit server-side UID/GID range. This code does not start a broker, wire a handler, create a user, or access a real host. `Store.Evaluate` remains an older policy-only helper, **not** a safe transport handler: only the writer performs executor verification and journal publication. The transport's nil handler still denies.

The writer opens and locks the private state directory, checks root owner/mode and each ancestor, reads the allowlist, ledger and high-water `head.json` under that lock, and records a higher observed allowlist epoch durably. Fleetrepo must seed `head.json` with version 1, the initial allowlist epoch and ledger generation under the same lock. An epoch rollback, ledger-generation mismatch, stale pending journal or interrupted `.next` stage fails closed. It re-reads the allowlist and ledger immediately before writes, before each executor phase and before route return; no in-process positive authorization cache exists. For new accounts it chooses the first unclaimed UID/GID in the configured pool after host occupancy checks, writes and fsyncs an exclusive journal, updates the journal before each account/home/config/socket/unit operation, verifies final state, atomically publishes and syncs the ledger and high-water generation, then removes and syncs the journal. Any failure leaves pending state for operator reconciliation; the code never automatically retries, deletes or repairs it. Existing bindings retain their name across GitHub renames and require host drift verification before a route is returned.

## Next seam / limits

A separately reviewed Linux executor must implement collision checks against NSS users **and groups**, UID/GID, home, socket ACL/directory, config and unit instances, fail-if-present phase operations and independent verification of NSS, home, ACL, config and unit for committed bindings. A root broker service must instantiate the writer with an operator-reviewed UID pool and install it as the explicitly supplied transport handler; do **not** use `Store.Evaluate` as that handler. Fleetrepo must declare the root-private state files, seed and update epochs and ledger generations under the directory flock, reserve the UID/GID range against independent allocation, own the socket/service/recovery procedures and test actual peer/guest isolation. No runnable service, gateway wiring, OAuth, live deployment or host user mutation is provided here. A non-cooperating root operator replacing files mid-transaction is outside the advisory-lock contract; in-flight rechecks fail closed when detected, but a privileged operator must coordinate through the lock.

## Verification

See the recorded validation in the issue. Tests are hermetic and inject an owner for disposable directories; production `NewWriter` always requires owner UID 0. Faults are injected at each executor phase and verification, and tests cover concurrency, alternate names, reserved host collisions, pending/staging state, revocation mid-operation and high-water drift. These tests do not prove the future Linux executor or Fleetrepo service.
