# Navigation design alignment — implementation result

Production uses the same rail content on desktop and in the phone drawer, a compact collapsed strip, a workspace page with the native start action before shared conversation lists, a compact account trigger and a return view ordered by new attention, ongoing work and remaining catalog conversations. The revised `Production/Sidebar v2` catalog renders new attention, working and read-only examples through production components. Existing send receipt and connection-recovery behavior was not changed.

## Decisions for review

- **Host-grounded state:** `agentPresentation` remains the source of activity, control and attention meanings. Live process presence does not imply an active turn; a seen question remains waiting; no process exit becomes *Valmis*. On the return view, read-only is a dashed tag separate from waiting, and a confirmed `missing`/`corrupt` history creates tab-local attention on first observation. Visiting clears attention, not the error label on the row; an `unavailable` history only says the source could not be checked. No provider error is fabricated from process state.
- **Recent order:** The native snapshot has no last-opened timestamp. The remaining section is labelled `Muut keskustelut`, preserves catalog order and displays all rows instead of hiding everything after three. The draft’s `Viimeksi avatut` would claim unobserved recency. For a more precise last-opened order the host would have to expose an observation.
- **Account:** The current snapshot contains `GitHub user <subject>`, not a verified personal name, image or email. The rail/menu/settings use `Oma tili` and `?` rather than rendering the subject as a name. Once a name is provided, the rail shows the first word and the menu/settings retain the full value. No email or avatar URL is invented; the profile-data issue owns those host facts.
- **Workspace and navigation:** Workspace name and disclosure stay separate targets. The start action is workspace-specific, not a global collapsed-rail `+` with no known target. The workspace page preserves native management controls and only labels the path facts the host supplies. Compact/mobile layouts keep one shared rail; the phone top bar names the selected view. Settings/logout composition remains owned by the settings round.
- **Visual differences:** See [comparison/NOTES.md](comparison/NOTES.md) for seven production/draft view comparisons at matched viewport/theme, static lab HTML and remaining gaps. The two synthetic data sets are not identical. Production lab shows read-only unknown-status history; it cannot demonstrate the draft's new attention and working cards. Those channels have deterministic tests and Storybook synthetic examples, not host-backed same-content visual parity. Jari's visual verdict after deployment is still outstanding.
