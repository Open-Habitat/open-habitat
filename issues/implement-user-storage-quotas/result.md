## Product implementation

The broker selects a committed bound UID and applies the gateway-supplied default hard limit before publishing a new account, journals incomplete provisioning, and fails closed when kernel quotas or an existing bound limit become unreadable. Bound-account quota read/set remains possible after admission revocation without readmitting that account. The broker uses `quotactl_fd` on host-selected `/home` with an O_PATH descriptor, compatible with `PrivateDevices=yes`, and requires both quota **accounting and enforcement** (`Q_XGETQSTATV` flags) at startup, before account mutation and on native reads/sets. Native kernel quota state is the only usage/limit record.

Gateway and root CLI share the durable default and per-bound-user limit writer. Administrators see limits, usage, filesystem capacity/free space and overcommit; people see only their own quota. Browser and root CLI use strict versioned storage contracts, aligned 1 MiB–1 PiB byte limits and GiB input. Daemon clone admission checks its own effective UID, native hard limit, usage and filesystem free blocks, with no legacy `~/src` source image or 20 GiB cutoff. Remote clone size cannot be known before download; kernel EDQUOT is final. A confirmed full quota has a distinct clone error and browser explanation. **Recommendation needing trust-chain agreement:** implement an explicit root-only, read-only-preflighted policy-transition receipt linking the original fresh receipt digest to the reviewed pushed-Fleetrepo policy bytes, with no branching or acceptance of unknown installed content. Only then retry the official successor chain. Do not disable the quota enforcement unit to satisfy the successor.
