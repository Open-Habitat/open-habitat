# Clean gate lab cases rewrite committed issue evidence

## Description

## Description

The full clean gate runs lab tests that unconditionally save captures into tracked issue evidence directories. On a clean checkout this modifies tracked HTML/PNG files and creates untracked evidence. The gate then rejects its own writes at final-checks. This prevents unrelated work from obtaining the required clean-gate receipt, even if the capturing cases pass.

Observed during run `01m5sda3wz2tmj1z7jgagc811p` at commit `47076eac` with `flock --shared /var/tmp/agent-scratch/.lease ./scripts/ci-local.sh --clean --json`, no TMPDIR override. Seven other browser/lab cases also failed; those are separate from this deterministic source-tree mutation. Go/contracts passed.

## Reproduction

Run the full clean gate on a committed clean checkout. `web/tests/lab-browser-editor.spec.ts` writes snapshots directly to `issues/editor-long-file-cannot-scroll/evidence/`; `lab-title-generation.spec.ts` writes to `issues/title-regenerate-arrow-spin/evidence/`; `lab-integration-trash.spec.ts` writes into `issues/trash-view-misses-integration-files/`. None of those capture calls is guarded by an opt-in capture flag. In the observed gate, all three wrote source-tree files; final `git diff --check` failed on generated HTML whitespace (exit 2), before the clean-tree check could report the rest.

## Expected result

Normal gate cases put ephemeral captures into ignored test output. Updating committed issue evidence is explicit opt-in only. The clean gate must not regenerate evidence.

## Evidence

Alder: `/var/tmp/agent-keep/rail-unread-01m5sda3/gate.log` (full output), `gate-input.txt` (commit/tree), `gate-generated-files.txt` (exact modified/untracked files), `gate-generated-evidence.tar.gz` (generated bytes preserved before restoring the checkout).
