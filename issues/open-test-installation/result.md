## Decisions for review

- No synthetic or disposable GitHub identity was available for a full OAuth callback, so first-login provisioning on the open edge was **not exercised**. Existing Jari login on pilot.19 was not exercised either. Broker `admission:any` and prior synthetic two-UID provisioning evidence support the configuration's intended behavior, but an actual new account and native `gh` credentials remain unverified until a willing account owner signs in.
- The old Fleetrepo release/rebuild operators still expect an Access assertion in some paths. The current open installation works, but a later successor/rebuild needs those verifiers adapted and tested before use; never replay the Access-protected admission operator against this open edge. Fleetrepo's `RELEASE-UPGRADE.md` calls out that limitation.
