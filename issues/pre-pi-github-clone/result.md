# Pre-Pi GitHub clone/import result

One explicit `POST /api/v1/onboarding/github/clone` accepts only an exact `full_name`. The gateway requires the broker-mapped session, same-origin write authorization and CSRF; it reconstructs the request on the verified mapped socket. The daemon checks the immutable peer/subject, native `gh api /user`, then fresh `/repos/{owner}/{repo}` metadata and canonical HTTPS clone URL. Native Git inherits only this UID's HOME/config and the installed Git credential helper (`nativegh` recognizes `!gh auth git-credential` or `!/usr/bin/gh auth git-credential`, after `gh auth setup-git`); no browser token, path or clone URL crosses the boundary. The daemon reserves a directory inside a descriptor-relative, owned, non-symlink `~/src`, rejects existing names (case-insensitively) and leaves a failed/uncertain checkout in place rather than retrying. It bounds children/output/deadlines, kills subprocess groups, and verifies the checkout, remote and named directory before success. Errors are fixed safe codes; the browser must reconcile through fresh native read-only observations before requesting a new import. This does not add a registry or enable Pi-gated routes.

Focused tests at `fc40a2e` passed for daemon refusal/collision/partial/cancellation/permission/symlink/rename, a native Git checkout with offline bare fixture, gateway CSRF and forged request rejection, and the gateway→daemon→synthetic gh/git socket integration for two broker-mapped subjects. An earlier clean CI invocation completed with `{"status":"passed","clean":true}` but the worktree acquired additional commits while it ran, so that invocation is not revision-specific evidence for the final implementation. Clean CI at committed `07c2741` passed (`status: passed`, `clean: true`), before the opt-in three-UID clone fixture was added. The final gate after that addition is recorded in the worker report.

The opt-in `scripts/test-repo-catalog-uids.sh` also passed in a networkless rootless container with two actual daemon kernel UIDs and a distinct gateway UID: each daemon performed one synthetic clone, refused an identity forged for the other subject, rejected a duplicate POST, and denied a foreign daemon UID at its socket. The gateway→daemon integration fixture exercises two mapped subjects on the same test UID; the container test exercises kernel UID separation without the browser gateway process.

Limits: all provider interactions were synthetic; no live GitHub, real credentials, real home, release or live systemd socket activation was tested. The container's fake git creates a synthetic `.git` tree, while a separate local-bare-Git test executes actual Git plumbing; neither proves live GitHub HTTPS credential exchange. A failure after POST can leave a partial checkout; no automatic cleanup or retry is promised.
