## Direction worth keeping

One visual tool use for a call, progress and saved result joined by call ID; preserve the order of text, thinking and calls; distinguish a user's local command from an assistant's `bash`; keep unreadable thinking and hidden extension content out; show boundaries for previews, truncation, aborted/limited responses and genuinely unknown content. ## Reconciliation needed before the draft becomes current

1. **Question history is not a durable native fact.** `extension_ui_request` and the browser's `pending_question`/journal can display a live request; the Pi session catalogue does not promise a saved question and resolved-answer entry on the selected native ancestry. The response promises a *permanent* `QuestionRecord` with outcome, including cancelled/timed-out questions. Do not build a parallel history store or imply those outcomes exist. For now show the current live question; a durable record needs an explicitly identified native source and a separately approved product decision.
2. **Settlement and model metadata have different scopes.** `turn_end` and assistant messages can occur multiple times before `agent_settled` (including tool use and retries); usage/model/stop reason come from particular assistant messages, not automatically one aggregate. A single end-of-run marker after observed settlement is plausible, but it must not claim an aggregate model/token total or move a per-message failure past a retry as if one final success. Preserve source association; show only supported metadata and unknown status when settlement was not observed.
3. **Tool-result metadata is screened intentionally.** `details.truncation` and a bash exit number are not currently in the safe browser projection. A parsed number from a free-text "Command exited with code N" is not authoritative structured metadata. Keep `isError` and known bounded text; show precise truncation, output sizes or exit code only after a narrow safe typed projection is implemented and validated. Similarly, a countdown, extension source name, label target and question outcome need their respective verified facts. `fullOutputPath` must remain private; full-content access is through revision-checked bounded block reads.
4. **Scope decisions in the returned handoff are not automatically user approval.** Its section labelled “Jari, 2026-10-05” asserts four choices without a decision in this repository: defer adjacent-tool grouping, collapse user messages at eight lines, defer edit diffs, and default bash previews to the end/others to the start with per-tool memory. Recommend the simple per-call tool row first and defer grouping/diff; allow expansion of long user text without losing the original; start bash at the tail and other tools at the head but keep the choice per displayed result unless Jari confirms persistent per-tool preference. Ask Jari to confirm these product choices before adopting them as settled design.
5. **Coverage is not complete evidence.** The package's `COVERAGE.md` has 110 `UNRESOLVED mapping` change entries, not actual diff contents. The handoff correctly declines to claim comments on each. The prototype supplies synthetic examples, not matching production captures for the 120 presentation gaps. It does not independently prove 200% zoom, focus/keyboard behavior, accessibility or live-to-history equivalence. The staging control simulates an 11-step story; it is not a native event replay. Compare matching content/state/theme/viewport against the previous references before calling any frames equivalent.
