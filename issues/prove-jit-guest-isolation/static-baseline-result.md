## Failure diagnosis and repair

The earlier `3037933` static seed carried `oauth.identities`, which `NewAuth` now rejects, and no broker state/socket. The disposable PID1 guest initially reported `gateway not ready`; bounded guest journal error-code diagnostics were added. Subsequent guest boots exposed further actual failures rather than presuming the first was exhaustive: missing `setfacl` in the pinned cloud image (`FileNotFoundError setfacl`), then broker startup refusal on a per-user ACL `group::--x` where the production verifier requires `group::---` with named-user search grants. A framed gateway-UID broker probe initially lacked protocol write-side shutdown; after correction the real broker authorized the prebound users and the full proof passed. ACL tools and `libacl.so.1` are copied by digest from the disposable VM-tools image onto the private product ISO, installed **only in the guest**, not the machine. The fixture uses the actual production systemd broker and daemon templates and byte-identical broker-verifiable daemon configs; no production authorization code changed.
