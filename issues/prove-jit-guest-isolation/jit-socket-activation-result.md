# Broker-gated JIT socket activation — verification in progress

Parent @prove-jit-guest-isolation remains **open**. No Fleetrepo or live host state was changed. This implementation makes the root broker, not the web gateway, start only a committed, validated per-UID daemon socket via the pinned Fleetrepo systemd gate. The start occurs after the binding ledger and head are durable and the pending journal is removed; the writer releases its exclusive lock so the Fleetrepo gate can take its shared lock. The broker verifies the exact gate dependency and command, active unit, socket inode owner/mode and UID-specific directory ACL before returning a route; an `authorize` never starts a unit and denies an inactive socket. It rechecks allowlist/epoch and binding after activation before any token handoff. No token is sent or normal session issued if activation fails; explicit future `ensure` can retry a committed binding, but never auto-repairs a journal or adopts drift. Commands and exchanges have finite deadlines. No `enable`, arbitrary service start or gateway privilege was added.

A stopped per-UID socket denies new session-backed operations without crossing to another UID. The failure is classified `state_unavailable`, so the existing session stays in memory for a later explicit safe reactivation; its request is denied meanwhile. On a reboot, the socket is disabled by design and the boot-time Fleetrepo ACL preparation remains mandatory before an explicit `ensure` may activate it; existing session requests are not silently activated. No automatic reboot activation is claimed.
