## Decisions for review

- Publishing is limited to the signed-in GitHub login as owner; collaboration and organization creation are not inferred from browser-provided owner text. The clone catalog can still show accessible repositories elsewhere.
- Remote creation uses `gh api POST /user/repos`, then a separate `git remote add origin`, then ordinary `git push origin HEAD` with a single verified HTTPS push URL. A remote with branches is not adopted; an empty remote is the recovery state after a lost creation receipt. The observation displays local HEAD and working-tree status without filenames or credentials.
- A GitHub OAuth session issued within five minutes, plus a fresh local authorization observation, is required for local disconnect. This removes local `gh` authorization but does not claim to revoke the OAuth grant; signing in again restores the native authorization.
- A remote GET failure does not prove absence: creation remains an explicitly confirmed request, and any failed/lost write is uncertain until a new native observation. There is no blind retry or force push.
