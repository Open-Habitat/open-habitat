# Named server and browser administration result

Gateway-owned durable `administration.json` stores the server name and administrator GitHub subjects under the gateway's private persistent StateDirectory. Ordinary users see the name (or hostname fallback) but cannot read the bound-user list or change settings. An administrator selects an already-bound user, including one whose daemon socket is stopped. Role removal is checked against current gateway state under the same mutex as the write, including in-flight browser writes. Browser roles do not select daemon routes or grant native data access. The existing root-only `revoke.sock` listener accepts `ADMIN` requests only after its kernel peer-UID check; the operator-facing CLI commands belong to `server-administration-cli`.

The broker's scoped `list` and `lookup` read operations return GitHub subject and Unix username only; they do not return daemon routes, home paths or credentials, and do not require socket readiness. The gateway and control listener serialize changes through one writer. A corrupt state file fails startup; a missing established file fails closed while running. Empty state has no administrators, and a root control grant can appoint the first one. The state survives gateway restart and release replacement when the gateway StateDirectory is retained.

## Decisions for review

- Use the gateway's already-declared `/var/lib/native-agent-host-gateway` StateDirectory for the private 0600 `administration.json`, separate from `sessions.json`. No new Fleetrepo directory or service is necessary; the release must retain the directory and enable the existing root-only revoke socket and gateway unit. The initial state is absent, with zero administrators. A first root operator grant uses the subsequent CLI issue; this issue supplies the control operation, not the CLI client.
- Show a bound user's existing Unix username and numeric GitHub subject, not an unverified full name or email. The broker binding ledger has no such profile facts. A role is keyed only by numeric subject and does not create a binding or admit anyone.
- The sidebar falls back to the first hostname label when the name is unset or temporarily unavailable; this is recognizable without presenting an arbitrary truncated URL. The administration page remains separate from personal Settings. A failed name save requires a fresh read before another write and retains the typed draft.
- Removing a role is allowed even if the target binding is gone or the broker is unavailable, so an operator can subtract stale authority. Granting requires a current bound target. Revoking a browser *session* alone does not remove that subject's administrator role; role removal is a separate action.
- Broker pagination compares binding generation, not allowlist epoch: the projection lists bindings regardless of allowlist membership. Broker responses remain bounded by its 4096-byte ledger limit.
