# GitHub account presentation — implementation result

The signed-in GitHub `/user` response now supplies display-only name, public email and the GitHub avatar URL in the browser session. One account presentation renders the first word of the name in the compact rail, and full name/email in the opened menu and Settings; an unavailable or failed avatar falls back to an initial. A missing name or public email prompts for it, with a skip path so a private email does not prevent use of the app. Profile edits use session CSRF and Origin and never set the provider subject, Unix binding or daemon route. Logout and subsequent login replace the session-scoped profile.

## Decisions for review

- GitHub `/user` `name` and public `email` are the source of displayed facts. We do not request a broader `user:email` OAuth scope or infer a first name from an address. The first whitespace-delimited word of a supplied full name is the compact name.
- Manually supplied fields are held only in the gateway session, not in a second account registry or a browser-local identity store. When GitHub still lacks them after a new login or gateway restart, the optional prompt recurs; skipping leaves `Oma tili` or an absent email rather than blocking native work. Durable fallback settings across devices would require a per-user native persistence decision.
- Only HTTPS `avatars.githubusercontent.com` URLs from GitHub are rendered, with `no-referrer` and an initial on load failure. The gateway neither proxies nor fetches profile images. No image means a deterministic initial or `?`.
- The display session contract is separate from the daemon snapshot because the gateway owns the OAuth profile and the daemon has no reason to receive personal display data or an authority claim.
