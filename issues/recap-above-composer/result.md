# Recap above the composer — synthetic result

A native recap now occupies its own dismissible card immediately above the composer, outside the transcript scroll. The header shows relative age, a dashed newer-message mark, an automatic-generation label when applicable, refresh and close icon actions. Refresh remains visible but disabled with its reason while Pi works. A pending manual generation renders a skeleton. The browser saves only the dismissed recap's native key and generation time, scoped by identity and conversation; dismissal propagates to other open tabs and a newer recap reopens the card.

The per-user daemon schedules automatic generation only after verified native settlement and more than three minutes without observed Pi/person message, tool or queue activity. A rejected browser command that never reached Pi does not restart the native idle clock. One timer and one in-flight guard belong to the daemon session; the native last-message key and Pi extension prevent duplicate work across tabs and reconnects. This does not depend on browser focus, reading or drafts. Automatic and manual recaps stay in Pi's native history rather than a second store; terminal-owned sessions remain read-only for generation.

Paired synthetic-lab captures: `lab-{1440,390}-{light,dark}-{current,stale}.{png,html}`. The `pi-recap` fixture compresses the three-minute timer to 600 ms; production uses three minutes plus one millisecond. Captures show the card at the bottom of a finished turn and, during a deliberately slow second turn, its stale mark and disabled refresh beside the composer. Compared with `design-system/drafts/Agentin vuoro.proto.html`, production retains the existing transcript's native message/tool presentation; on a 390 px phone the automatic label can wrap onto a second header line instead of shrinking the controls. This is deliberate for readable controls and text at small widths.

Verification: synthetic Go timer gate tests cover multiple tabs, a running turn, native activity cancellation/rearming, rejected commands and a single idle request; the browser lab test covers automatic generation, native persistence, second tab/reconnect, an unsent browser draft, manual refresh idempotence, stale/disabled state, cross-tab dismissal and a newer recap. The pinned Pi native extension test also passed with disposable dependencies. Real Pi model/provider behavior and distinct kernel UID isolation are not proven by these fixtures. No full clean gate was run.
