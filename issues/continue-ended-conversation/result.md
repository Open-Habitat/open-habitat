# Browser continuation slice — synthetic result

The browser can request an explicit bodyless continuation of a browser-leased Pi conversation. It validates the CSRF-bound response, reads status and native history before enabling the editor, keeps the previous native outcome uncertain, and never automatically retries a continuation or resends a prompt. A lost 503 reply leaves a tab-scoped marker; status plus a successful native-history read can reconcile it without a second POST. If the write never reached the daemon, a fresh **explicit** status/history check can offer a separate deliberate second press; no status poll reposts a write. `writer_conflict`, `read_only_history` and `control_uncertain` are displayed as distinct reasons. Terminal and foreign histories have no current browser lease and never show this action. Stream failure triggers an HTTP status/history resnapshot rather than claiming SSE replay.

## Blocking server request and deviation

The private `GET /api/v1/conversations/{id}/status` currently has only `state: uncertain` for both **reaped/ended children** and **live children whose RPC outcome is uncertain**. `native_history: readable` means JSONL was read, *not* that the writer has exited. The browser cannot positively identify an ended conversation from those two fields. This slice shows a quiet continuation affordance on `uncertain` + readable + current-login lease, and the server's writer lock denies it with `writer_conflict` while a child is live. That is safe for native writes, but it is a presentation deviation from the acceptance criterion **only ended conversations offer continuation** and from `docs/ui.md`'s “when previous work is known ended”. Do not claim that criterion complete until night:rest exposes a verified ended/continue-eligible observation in the validated private status (or another equivalent browser-readable proof), then gate this affordance on it and cover live-but-uncertain with a browser test. Please relay this request to `issues/night-2026-09-30/ui-status.md`; this run may not edit other docs or `internal/`/`contracts/` while rest owns them. The route is not in generated `web/src/contracts/`; the manually validated private protocol stays separate pending rest's contract decision. Do not present the provisional stream as published `/api/v1/events` replay.

No view-specific CSS, hard-coded colours or synthetic user data were added. The v2 shared composer surface, notices and button primitives carry the action. Existing reading position, drafts and uncertain-send acknowledgement rules are retained. The full-title and status labels remain as agreed despite the design draft's alternative.
