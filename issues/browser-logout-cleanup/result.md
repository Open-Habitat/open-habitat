# Result: browser logout cleanup

`App` now owns one local cleanup path for explicit logout, observed expiry and a confirmed different `web_identity_id`. It fences pending snapshot/catalog callbacks, stops the tab-wide journal and reconnect timer, disposes the conversation store (including pager cancellation), clears Redux and person-specific UI state, and deletes `nah:<identity>:` drafts and pending-command markers. The old identity's callbacks cannot write into a new identity's view. At a login boundary after reload, when the previous identity is no longer known, it removes all validated identity-scoped keys while preserving global onboarding keys. A failed server logout leaves the local data hidden but shows an explicit retry warning; local cleanup is not presented as server-side revocation. A later same-person or different-person login starts with a new store and journal.

## Review and design

A focused two-model final-diff review was proportionate because this bounded change crosses the browser's privacy boundary and several async owners; a broad panel would not add useful coverage to the accepted design. Claude Fable found one confirmed, occasional reload/expiry leak: after a page reload `priorIdentity` was unknown, so old drafts remained in sessionStorage. GPT-6 Astra verified the cause, the schema-bounded cleanup and the absence of a reachable late-page/status/journal write path; it pointed out that the first browser regression could pass if the old page had already observed a 401, so the test now seeds stale storage in the new document before App loads. Assessment: **CONFIRMED / OCCASIONAL / NEUTRAL readability / MINOR architecture / HIGH confidence / FIX**, implemented and tested in this issue; no residual finding merits a follow-up issue. The design authority did not change: `App` still owns session transitions, while the journal/store/pager own their disposal primitives.
