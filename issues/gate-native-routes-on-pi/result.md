# Pi gate: fail-closed intermediate

The daemon now verifies the mapped peer and gateway identity, then checks native Pi `openai-codex` OAuth afresh **before** snapshot, history or content handlers can read native sources. Missing or unknown status returns `428 pi_onboarding_required`; the gateway reauthorizes the broker binding on each request, routes to the mapped socket and substitutes a fixed redacted error. Authenticated `GET /api/v1/onboarding/pi/status` returns only `usable`, `missing` or `unknown` with `no-store`. New v1 status schema, fixture, scenario and generated Go/TS fingerprints accompany the route. There is no browser-selected UID, socket or provider and no credential data in the response. Unimplemented commands and repository endpoints remain unimplemented, not bypasses; any future native route must be gated before native access.

**Not complete:** Device-code start/cancel and per-session attempt ownership are not exposed. The daemon's fixed pinned runtime location (`/opt/native-agent-host/pi/...`, Node `/usr/bin/node`) requires an operator-controlled installation before native status can be usable; absent runtime means `unknown`, never an open gate. No live credential, test-host deploy, production UI wizard, synthetic distinct-UID integration or host-backed browser denial proof is claimed. Existing terminal histories remain read-only. This issue remains open and no `Fixes-Issue` is stamped.

Focused synthetic daemon gate tests prove trust is checked before status and that missing/unknown/stale native state prevents a native handler call; gateway socket tests exercise authenticated status and redacted blocked snapshot responses across two synthetic mappings with the **same** test UID, not two isolated UIDs. Full clean gate and final independent security review evidence are recorded after they run.
