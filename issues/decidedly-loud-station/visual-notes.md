# Repo chooser narrow-width evidence

**Synthetic lab only; not yet reviewed by Jari.** At 390 × 844 CSS pixels, the audit's baseline [before](chooser-screenshots/before-390.png) has its action below the captured viewport. The updated chooser keeps a selection count and a clearly named continuation action below a bounded, independently scrolling catalog: [empty selection](chooser-screenshots/after-390.png), [one selected](chooser-screenshots/after-selected-390.png), [filtered with selection retained](chooser-screenshots/after-filtered-390.png). The latter two are from the same lab session. The document measured 390px wide, with no horizontal overflow. The earlier audit screenshot was copied without alteration; the others come from this worktree's synthetic lab, not a live host.

The footer stays in the chooser rather than floating across the app. The list is bounded by viewport height, so the action is available before scrolling through 52 repos; the footer sticks to the bottom edge while the card itself scrolls. The filter never removes an existing selection. Keyboard and host-backed synthetic-browser checks are recorded by the regression tests; this visual comparison does not prove live OAuth or native checkout.
