# Browser UX audit — synthetic lab, baseline `1d72713b4189fdcf7071d343eaec738ea85dd27f`

**Recommendation:** fix send acknowledgement/draft safety first, then the conversation layout and error recovery. The onboarding journey is comparatively clear. This is an audit of the checked-out baseline, **not** of the concurrent conversation, shell/navigation or onboarding workers' later changes. The issue is an **unlaned intake item** for Jari's next-round decision, not a replacement for their existing implementation issues.

## Method and limits

`npm ci --prefix web`; `PLAYWRIGHT_BROWSERS_PATH=$PWD/.cache/ms-playwright npx --prefix web playwright install chromium`; `scripts/lab.sh start` → `https://127.0.0.1:4175`; headless Playwright in a fresh isolated browser context, synthetic Alice/Bob OAuth, synthetic homes and fake Pi, desktop 1440×900 and 390×844. Screenshots are synthetic and live only in [screenshots/](screenshots/); paths and account names in them are invented fixture data. Explored sign-in/provider, `pi-onboarding` chooser → first repo clone → Pi gate, `/workspaces`, terminal history, create/send (`hidas`, `hylkää`, `kaadu`, `pitkä`), settings/logout, Alice→Bob in one tab, expiry, keyboard Tab/focus, narrow viewport, and `empty`, `missing`, `error`, `partial`, `delay`, `native-error`, `pi-blocked`. A separate `pitkä` turn produced a many-paragraph response; an eight-turn synthetic controller conversation crossed a paginated history boundary, and another echoed Unicode (`Ääkköset 🦊 中`) plus 3,800 consecutive `x` characters without desktop document overflow ([long-line screenshot](screenshots/unicode-long-line.png)). The checked-in lab seeds only short terminal histories (2 turns at most), so *a 65 KiB unbroken line and very deep native histories remain unproven*. Existing implementation tests should cover those, or extend the synthetic fixture before calling that journey visually accepted. No live provider, real Pi, real UID isolation or live host tested. No clean gate rerun (issue/evidence only).

## Defects — ordered by impact

### 1. High · A rejected send loses the user's draft and locks retry

**Status (conversation robustness follow-up):** Rejected sends now retain their draft and release the retry lock on confirmed rejection; accepted sends clear only the submitted text after the matching native acknowledgement. Uncertain sends retain their text and never retry automatically. Synthetic regression evidence is in `web/tests/lab-conversation.spec.ts` and `web/tests/browser-conversation.spec.ts`.

**Where/experience.** Create a conversation in `aurinkokello`, type `hylkää`, press **Lähetä**. The fake Pi returns `rejected`. The editor becomes empty (`inputValue() === ""`); the UI says *Viesti hylättiin. Luonnosta ei lähetetä automaattisesti uudelleen* but also *Aiemman pyynnön tulos epävarma* and disables sending until the native state is resolved. The same premature clearing is visible while `hidas`/`kaadu` are only `accepted` with acknowledgement still pending. Evidence: [rejected editor](screenshots/keyword-hylkää.png), [pending result](screenshots/keyword-kaadu.png); Playwright output captured `EDITOR hylkää` as empty and the rejected/uncertain status text. Source corroboration: `BrowserConversation.tsx` calls `changeDraft("")` immediately after HTTP `send()`, before `refresh()` determines the native acknowledgement, and the ambiguous receipt only clears on accepted + idle + readable.

**Why it matters.** Work is lost precisely when a send fails, and a contradictory uncertain status prevents a deliberate corrected retry. [Agreed UI: message/acknowledgement](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#viesti-vastaus-ja-työn-ohjaus) says rejected and uncertain sends retain their text and distinguishes pending, accepted, rejected. [Recovery](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#katkos-ja-epävarma-tulos) forbids automatic duplicates, not an informed manual retry. **Fix:** retain a command-specific submitted text/version until the status confirms accepted; clear only that version on acceptance, restore/reveal rejected text, distinguish rejection from unresolved outcome and unblock on confirmed idle state. Regression-test `hylkää`, `hidas`, `kaadu` and reload.

### 1b. High · Fresh replies disappear when a conversation crosses a history page boundary

**Status (conversation robustness follow-up):** The writable feed now walks forward from its last native entry instead of treating the oldest page as the live tail. The paged browser regression checks that new content beyond page one is visible without a manual load and does not displace the reader.

**Where/experience.** In a fresh controlled chat, send eight short messages sequentially, waiting for each send button to become enabled. Messages 1–6 and their Pi replies appeared. After message 7, the user's message appeared but its answer did not; after message 8, neither message nor reply appeared even after waiting another 3.5 seconds. The UI offered **Lataa seuraava historiasivu**. Clicking it revealed the missing answer and message 8. The live controller still reported the turn complete. Screenshot: [before manual pagination](screenshots/pagination-after-8.png) and [after manual pagination](screenshots/pagination-confirm.png); exact observation in synthetic console log `.cache/lab/audit-pagination-confirm.log` (`turn 7 … answer visible=0`, `turn 8 user visible=0`, then answer shown after pagination). This repeats the first timed-out seven-turn attempt; it is not merely the `pitkä` response still generating.

**Why it matters.** After several ordinary turns a person thinks Pi stopped responding or their prompt was lost. The [agreed UI](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#luonnokset-lukukohta-ja-huomio) requires new content to appear or an *Uutta sisältöä* indicator while preserving the older reading position; pagination of *older* content cannot hide the latest turn. **Fix:** reconcile live tail against the actual newest native entries independently of the historical page cursor; retain a stable reading anchor when fetching older pages and verify 8+ turns with the real controller and synthetic Pi. Coordinate with the conversation worker.

### 2. High · Failure replaces the entire existing view instead of leaving stale content readable

**Where/experience.** The `error` scenario displays only *Yhteyttä ei saatu* and a **Päivitä** control. `App.tsx` calls `unavailable()` on a failed refresh; its current error branch renders this generic panel, with the previous snapshot dropped by the store. After reading a conversation, a server interruption therefore removes the last content rather than marking it stale. Screenshot: [error panel](screenshots/scenario-error.png) (the fixture scenario was switched before navigation; verify the same transition after a populated conversation in regression tests).

**Why it matters.** The user's reference material disappears during an outage. [Agreed UI: interruption](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#katkos-ja-epävarma-tulos) expressly keeps last received content readable but stale, and disables writes pending freshness. **Fix:** retain the current *identity-bound* verified view while the same authenticated session is reconnecting; mark it stale, disable writes, and wipe it on identity/session loss. Preserve the existing fail-closed Alice→Bob behavior; never carry old identity content across logins.

### 3. Medium · History cannot fit a narrow/zoomed reading viewport

**Implementation update (Markdown-rendering worker):** Feed/grid/card min-content widths are constrained; the synthetic seeded history at 390 CSS px now has document width 390px. Code and tables scroll inside their own panes. A narrow synthetic browser regression was added; Jari's 200% zoom and visual acceptance are still outstanding. See `../complete-conversation-ui/markdown-visual-notes.md`.

**Where/experience.** At 390 CSS px, `/agents/pi:a1a1a1a1-0000-4000-8000-000000000001` reports `documentElement.scrollWidth = 1032` vs `clientWidth = 390`, while `/workspaces` and `/settings` both fit 390. The rendered history/feed is at least 700px wide, so messages/actions are clipped and require horizontal panning. Screenshot: [history at 390px](screenshots/history-narrow.png). Keyboard Tab still traverses the rail and focus outlines are solid (not an overall keyboard failure).

**Why it matters.** Mobile is out of scope, but the [design's 200% zoom requirement](https://github.com/maintainer/native-agent-host/blob/0d1a53160772be64daa00879536c8103bbd3d0e1/design-system/production-v1.md) and [UI accessibility requirement](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#designin-lähteet-ja-toteutuksen-arviointi) disallow horizontal coverage loss when zoomed. **Fix:** remove feed/min-content minimum width, give content cards `min-width:0`, contain only code/long lines in a scrollable code pane, keep controls inside viewport. Check 1280px at 200% zoom as the normative acceptance case, then 390px as stress evidence.

### 4. Medium · Native conversation history displays Markdown source instead of formatted Markdown/code

**Implementation update (Markdown-rendering worker):** Shared user/history-assistant Markdown rendering now uses pinned React Markdown, Remark GFM and Rehype Sanitize, without raw HTML; fenced code has a copy control and long code is expandable. Synthetic screenshots and adversarial component tests are in `../complete-conversation-ui/markdown-visual-notes.md`. Human visual acceptance and the remaining ADR rendering work (Shiki worker and parsed Pi edit diffs) are not claimed.

**Where/experience.** The seeded terminal answer shows literal backticks, ` ```json ` fences, JSON and inline command delimiters inside a plain text card rather than a readable formatted code block with code-copy affordance. Screenshot: [history rendering](screenshots/history.png). Tool output itself has a copy control; this finding concerns assistant message content.

**Why it matters.** Routine Pi answers and code reviews become harder to scan/copy. [Agreed UI: Markdown/code](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#viesti-vastaus-ja-työn-ohjaus) explicitly requires readable Markdown and copyable code. **Fix:** use safe Markdown rendering with inert HTML and bounded code blocks in the shared message component; render backticks and fenced code with a code-copy action, and test malicious HTML, Unicode and very long lines. This belongs with the concurrent conversation work, not a second renderer.

### 5. Medium · Newly started chat is buried below a read-only workspace report

**Status (reverified on current main):** The conversation-experience work already hides workspace details when a conversation is selected (`App.tsx`), puts the editor in the primary pane and scopes the read-only notice to terminal history. The query-param route remains: route convergence is the separately listed design question, not changed here.

**Where/experience.** After **Aloita uusi Pi-keskustelu**, the main pane still begins with a four-row filesystem/Git status card and a prominent blue notice *Vanhat Pi-historiat ovat vain luettavissa*; the *Pi-keskustelu* and editor are below them. First send may be below the fold. Screenshot: [new chat](screenshots/conversation-new.png). URL is `/workspaces/:id?conversation=pi:…` rather than a conversation path, while terminal histories use `/agents/:id`.

**Why it matters.** The primary action is displaced and the read-only message appears to apply to the new writable chat. [Agreed UI: navigation](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#kirjautuminen-ja-työtilan-valinta) separates read-only native histories from new writable conversations and requires durable deep links; [production routes](https://github.com/maintainer/native-agent-host/blob/0d1a53160772be64daa00879536c8103bbd3d0e1/design-system/production-v1.md) specify a conversation route. **Fix:** make a selected browser conversation the primary pane, move workspace facts behind details, scope the read-only warning to terminal history, and converge on the agreed route after deciding how controller session IDs map to native IDs. Coordinate with the shell and conversation workers.

### 6. Low · State labels in writable chat leak protocol words

**Status (reverified on current main):** The conversation header already translates each state to Finnish. The remaining raw state in the conversation picker is now translated too; no protocol enum is displayed in this flow.

**Where/experience.** A new chat shows `idle`; after sending, `accepted` or `rejected` is used as the dominant header state. See [new chat](screenshots/conversation-new.png) and [rejected send](screenshots/keyword-hylkää.png). The neighboring labels are Finnish.

**Why it matters.** `accepted` is ambiguous: HTTP acceptance, native acknowledgement and actual Pi progress are not the same. The [UI decision](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#viesti-vastaus-ja-työn-ohjaus) asks for understandable send stages and agent progress. **Fix:** translate the status through an explicit Finnish display model (e.g. waiting/working/finished/rejected, with receipt separately), rather than exposing backend enum values.

## Polish — after the defects

- **Medium · Terminal history titles are indistinguishable.** Four separately seeded histories have header *Uusi keskustelu* and rail titles with no recognizable topic, although their contents differ. [History screenshot](screenshots/history.png); [UI title behavior](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#luonnokset-lukukohta-ja-huomio) calls for fallback to the first user message when generation fails. Offer a bounded, safe first-message fallback for legacy histories, without inventing a generated host title. Confirm title source semantics before changing host ownership.
- **Low · Onboarding repo list is dense but workable.** The chooser offers search and shows repo names, dates and selection count; first-page synthetic repo pagination reaches `last` without blocking first use. At 390px the action is pushed below the 50-item list ([chooser](screenshots/chooser-narrow.png)); a sticky footer/count or clear “continue without selection” action would shorten the journey. Not a functional defect; coordinate with completed onboarding work.
- **Low · Generic connection warning is loud during healthy activity.** The persistent top banner says *Workspace-muutokset ovat vain luku -tilassa* over every healthy screen, including an actively controlled browser chat ([workspace](screenshots/ready-viewport.png), [history](screenshots/history.png)). The distinction is true (workspace mutations vs chat control) but repeated across pages; consider placing the capability reason next to disabled workspace actions and using the global banner only for connection/auth issues per [production UI](https://github.com/maintainer/native-agent-host/blob/0d1a53160772be64daa00879536c8103bbd3d0e1/design-system/production-v1.md).

## Design questions for Jari

1. **History vs browser chat location.** Recommend a single agent conversation route with native-ID-based deep linking, and a secondary workspace-details view. The baseline's query-param controller conversation and `/agents/:id` read-only history have different visual and routing identities. This touches the browser/host contract; settle with Jari before a new route design. [Route agreement](https://github.com/maintainer/native-agent-host/blob/0d1a53160772be64daa00879536c8103bbd3d0e1/design-system/production-v1.md).
2. **Legacy terminal history title fallback.** Recommend first-user-message excerpt until host title availability is clarified, rather than four identical *Uusi keskustelu* entries; confirm whether a UI-only fallback is acceptable or title must be host-supplied. [UI title agreement](https://github.com/maintainer/native-agent-host/blob/90ef1565f1df46da9ade73b885db2d5bb2c4a837/docs/ui.md#luonnokset-lukukohta-ja-huomio).

## Positive checks and evidence boundaries

- The initial sign-in is explicit ([sign-in](screenshots/sign-in.png)); the fake provider offers Alice and Bob, and first-use chooser followed by a synthetic first clone reached [Pi setup](screenshots/pi-setup.png). `pi-blocked` also returned the onboarding gate. This proves only the synthetic host path, not real OAuth, credential transfer or real Pi.
- `empty`, `missing`, `error` and `partial` showed distinct user-facing states ([empty](screenshots/scenario-empty.png), [missing](screenshots/scenario-missing.png), [error](screenshots/scenario-error.png), [partial](screenshots/scenario-partial.png)); `delay` settled, `native-error` did not change the already usable session. No false success conclusion for those fixture knobs.
- Account menu → [settings](screenshots/settings-narrow.png) → back and sign-out worked; Alice→Bob after sign-out replaced the visible workspace identity ([Bob](screenshots/bob-after-alice.png)), and `/fixture/expire` + reload returned to the [sign-in view](screenshots/expired.png). This does **not** prove hidden draft/scroll storage was wiped: test that separately. Focus was visible as a solid outline on the skip link, rail toggle, search, refresh and workspace disclosure in the first ten Tabs. Full keyboard-only task completion, focus recovery from dialogs and Axe were not independently rerun here.
- The `pitkä` turn eventually produced an extended, readable plain-text response and a confirmed acceptance message. Unicode and a 3,800-character unbroken line were echoed without desktop document overflow. The eight-turn pagination test **failed** as described above. A 65 KiB single line and performance threshold were not measured.
