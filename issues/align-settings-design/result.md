# Settings design alignment result

Deployable Settings composition on production components: Tili, server connections, appearance and browser session use the shared panel and control vocabulary. Both Settings and the rail account menu open one confirmation before ending the browser session. Cancel leaves the session and browser state untouched. The successful logout still clears person-scoped browser state and the host session; it does not delete server credentials or stop agents. [The shared view comparison](comparison/NOTES.md) records synthetic images, offline HTML, compared revision and gaps.

## Decisions for review

- **Account facts:** The current snapshot exposes a placeholder provider subject rather than a verified full name, email or avatar. Keep the same `Oma tili` / `?` fallback on the rail, menu and page; do not present the subject as someone's name. Show a verified name when available and an optional native GitHub login as a monospace identifier, without conflating the two. Do not label a fallback as a verified GitHub profile.
- **Connections:** The snapshot gives a native GitHub connection state, but no OpenAI settings state or reconnection intent. Show the one evidenced row, preserve partial/unknown as such, and explain that logout is browser-only. No fabricated OpenAI connection, failure reason, pending code or check/reconnect button appears. The native-settings issue owns those functions and the profile issue owns full identity fields.
- **Logout:** Both account entry points confirm the effect using the same modal, with keyboard-accessible cancel and confirm. Confirmation separates browser data from server-held work and credentials; no network logout occurs on cancel. After an unconfirmed logout failure the existing signed-out safety screen remains, explaining that the server session may still exist and offering a retry. The onboarding sign-out retains its existing flow rather than silently changing unrelated ownership.
- **Shared components over draft specifics:** Settings keeps the production radio group, list rows, button and status mark instead of copying the prototype's segmented-button logic, refresh/re-auth placeholders or host-unsupported state examples. Phone cards wrap rather than compress text; scroll is allowed. The draft's dark mode must be selected through its own control for a true comparison.
