# Inert broker admission core result

`internal/provision/` provides strict bounded v1 `ensure` / `authorize` request and reply parsers; canonical positive GitHub numeric IDs, a candidate handle without UID authority, closed failure vocabulary, derived route, and root-owned allowlist/ledger admission checks. New IDs receive **no route**: the future privileged service must perform serialized collision, NSS, UID pool, journal, account and unit checks before publishing a binding. Committed IDs retain their immutable username/UID across a changed candidate login. Missing or malformed state, unknown/revoked IDs, duplicate IDs/UIDs/names, unsafe state files, and pending state deny admission.

State format: `allowlist.json` (`version:1`, positive `epoch`, `ids:[{"id":"42","alternate":"optional-safe-name"}]`) and `bindings.json` (`version:1`, positive `generation`, `bindings:[{"id":"42","uid":1001,"username":"alice"}]`) in a private root-owned directory. No file contains token material or caller-supplied paths; sockets are derived from committed names. Alternate names are operator-owned approvals, not request authority. The production `Store.Evaluate` requires root ownership. A private owner override exists only for hermetic package tests.

**Boundary:** No root service/listener, peer check, NSS inspection, lock, account allocation, credential handoff, callback change or dynamic gateway routing has been implemented. Existing static gateway admission is unchanged. State reads are not transactional across files; the next broker service must hold its root-only writer lock while evaluating, enforce atomic publish and durable epoch/generation changes, handle pending journal and filesystem drift, then wire per-request and SSE reauthorization. A routed binding here is a policy result, not proof that a socket, unit, home, or native credential is healthy. These fixtures do not establish guest UID isolation or live login. No guest, Fleetrepo, credentials or cloud changes.
