## Encountered implementation problem

The previously landed pager could not fetch through the gateway: its URL encoded the `pi:` separator (`pi%3A…`) and the gateway's history query allowlist rejected `before` entirely. Both yielded HTTP 400 in a real synthetic browser request, despite pager unit tests passing with mocked fetch. The correction keeps the colon canonical in the URL and permits `before` but not `before` with `after` at the gateway. This fixes the existing route rather than introducing a new history protocol.
