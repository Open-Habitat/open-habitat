# Result: recent conversation windows

The read-only slice from the preserved worker was adopted and finished. `ConversationStore` now supplies both read-only and controlled histories, and `BrowserConversation` keeps its component mounted across conversation IDs. A warm controlled return reads its saved window and status without a status or history GET; the existing per-conversation EventSource still closes and opens on a switch. Replacing that connection with one tab-wide stream is explicitly @one-browser-event-stream's work. Drafts, uncertain send receipts and continuation outcomes remain separate from saved history.

## Verification and measurements

- Deterministic store tests cover deferred cold windows and page/event races, confirmed missing history, native-key replacement and contradictory order, overlap and missing boundaries, bounded reconnection that finds or drops the old range, restart/gap recovery, background status notifications, identity disposal, 51st-window eviction, grouped-tool anchor keys, and nested read ownership. Synthetic Chromium tests exercise controlled warm return, scroll-back anchoring, read-only warm return, separate drafts, uncertain command outcomes and live provisional frames.
- Synthetic controlled return: **0 status/history or other non-stream API requests**, **59–95 ms** from navigation start through two animation frames (includes the intervening workspace navigation; not an isolated A↔B paint measurement). The per-conversation EventSource reopens. This is host-backed local synthetic evidence, not WAN p95 or a 16 ms guarantee. The accepted baseline measured cold read-only switches at 108/117/100/116 ms with one history GET; it did not measure controlled SPA switching.
- Synthetic read-only warm return: **0 API requests**, **136 ms** in observed local runs. Ten backward reads joined 251 entries from a 25-entry tail, including a synthetic 40,000-character non-ASCII output (about 80 KiB UTF-8) near the old end. Chromium CDP reported whole-app live JS heap **25,902,800 → 65,293,756 bytes** between 25 and 251 synthetic entries, without forced GC. This is not retained window size or a measurement of real large Pi outputs. The 51-window LRU is proven by unit test, not a browser profiler.
- `TMPDIR=/var/tmp/native-agent-host-windows-final NAH_PORT_BASE=41381 ./scripts/ci-local.sh --clean --json` passed on committed `01433ec` with `{"status":"passed","clean":true}`: 47 web unit, 73 component, 116 browser-host and 13 lab tests, followed by Go/race, contracts, VM self-test and release packaging. Later stale-control and test-race corrections passed targeted tests; a final clean gate on those commits is pending.

The cold-open test exposed a legitimate race: a newly created native history can move from `missing` to `present` as Pi writes. A confirmed missing status can open an empty window without a speculative history request, but a subsequent journal event can trigger a read. The test now proves no history read *before* status returns rather than asserting that a later write cannot cause one. This keeps the accepted state model; no architectural change was made.

## Review and limits

This is a bounded implementation of an accepted design, but the diff crosses asynchronous history, journal and control state; it justified one focused final-diff review rather than a broad panel. Claude Fable proposed five reproducible defects. Local tests confirmed them; GPT Astra tried to refute the fixes and narrowed two residual paths (metadata-only cursor advancement and multi-page reconnect ownership). Both were repaired and tested. No residual finding met the filing bar. The review and assessment are in ignored `history/review-recent-conversation-windows.md` and `history/assessment-recent-conversation-windows.{json,md}`; all durable reasoning is summarized here.

Not verified: production WAN click-to-paint/p95, real-user or real-output retained heap, separate-UID isolation, terminal Pi writes, or a tab-wide stream (next wave). No screenshots from a real account were captured.
