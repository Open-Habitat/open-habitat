# Workspace lifecycle — guarded local management, deletion disabled

## Decisions for review

- Adopted the conductor's narrower deletion guarantee (2026-10-06): pinned descriptors for traversal, never remove contents of a substituted target; a same-UID pathname race can move a substituted directory into a private quarantine, but must be recoverable on mismatch or crash. Linux provides no atomic compare-inode-and-rename syscall. This decision is recorded in `docs/architecture/workspaces.md`.
- **Deletion is disabled**, not a best-effort `rm`: a recoverable quarantine and verified process/worktree/mount observers are not yet implemented. In particular linked worktrees outside `~/src` and processes owned by other tools are unknown effects; allowing deletion without them would violate the issue's safety boundary. No delete endpoint is mounted. The browser states the limitation instead of presenting an unsafe confirmation dialog. A later implementation needs a quarantine recovery protocol and fresh preview, exact-name and inode confirmation, managed-process exit verification and conservative worktree/mount blocking.
- Local creation, name edits, hide/restore and Git initialization use the user's daemon and are re-observed from native files. Creation carries a source-inode token; target writes carry a workspace-inode token. Stale targets, unreadable source listings and replaced sources reject mutations; a confirmed unrelated bad entry does not block clean targets. First annotation mints a stable ID instead of persisting the path-derived fallback, and the UI navigates to it. Hidden state is presentation only, under the user's XDG state path. If optional state is corrupt, visibility writes are blocked, without replacing it.
- Creation requires an existing trusted `~/src`; it does not provision the storage volume. A mutation whose native write succeeded but whose final verification fails returns a partial/uncertain error; the UI refreshes native state rather than retrying automatically. Git initialization uses an independent bounded context so a disconnected tab does not cancel it. No new workspace registry is maintained.

## Limits

No delete/preview process exists. The independent critical review (`history/review-workspace-lifecycle.md`) found four actionable defects; an independent verifier challenged and confirmed the relevant failure modes. Each was repaired in the candidate and assessed in `history/assessment-workspace-lifecycle.{json,md}` (ignored scratch; findings are explained here). A second independent review of the full final diff found three further localized fixes: bounded body parsing before the shared writer lock, rejecting special-file user state without blocking snapshots, and a per-repository Git exclude when adding settings to an existing Git checkout. The same review's other suggestions were not adopted: an API-only hidden-state transition was too rare to justify a cross-file migration; a failed create intentionally leaves inspectable native state instead of risking a pathname cleanup; and display-name controls had no reachable unsafe renderer. Tests cover the three new fixes. Browser tests are synthetic and cannot prove UID isolation or safe interaction with real processes, mounts or out-of-source Git worktrees. Synthetic lab captures of the home creation control and detail settings/deletion notice are in `lifecycle-{home,detail}.{avif,html}`; the lab does not mount the lifecycle write route, so these captures cannot prove a successful mutation. Visual fidelity awaits Jari's deployed review; no real user data was used.
