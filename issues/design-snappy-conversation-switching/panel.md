# Independent design panel (2026-10-02)

Full verbatim responses and continuation: [panel-raw.txt](panel-raw.txt). `/llm-panel` design-mode role prompts ran concurrently on distinct models: browser-performance (gemini-3.8-flash, thread `api_33a65ea459074df098fa0185314ad2ef`), event-integrity (deepseek-v4-pro, `api_f7bb96e71d0f4191b6f175d154807573`), security (claude-fable-5-1, `6a0784a7-5b8d-4d78-8768-a23dc102818c`). Deepseek asked whether reload counted as recent, whether native files may be rewritten, and for the history contracts. A single continuation supplied those files and clarified: recent means this running tab, native history may change; the reply is included in the raw record. This is independent ideation, not a model vote.

- **Browser-performance:** one global stream and 3–5 warm windows, dispatch settled entries locally and avoid React updates for background deltas; no IndexedDB because it cannot serve synchronous memory switches. Its proposed immediate render of stale windows is acceptable only with unmistakable stale/offline labeling and disabled actions.
- **Event-integrity:** one global cursor and per-window fences; keep cold parallel status/history fetch, invalidate on global gap, and do not equate a settled event with a fresh history read when external edits are possible. Proposed an extra client journal ring, which we reject: the windows already receive events eagerly, and replaying from another ring adds a second bounded state machine without a demonstrated benefit. Its initial statement that `history.entry` is only a hint is stronger than the contract: the daemon derives it from checked native history; direct bounded append is legitimate when sequence and membership are proven, but it cannot establish that externally rewritten earlier entries are unchanged.
- **Security:** no persistent conversation content; per-origin IndexedDB persists across logout and its deletion is asynchronous. Retain identity-scoped memory only, evict synchronously on login loss / identity replacement; a retained continuation proof must not authorize a write. Status/native revision comparison it suggested is invalid in current code (status uses stat, history uses hash); no design relies on comparing them.

**Synthesis:** A plus D as a cold/recovery fallback; no extra client event ring, disk store or all-conversation prefetch. Eager dispatch for *opened retained windows* (native entries and bounded live state); ignore unvisited payloads after validating/advancing the global cursor. Central stream owns integrity. A selected stale window may show old text labeled stale while recovering, but controls remain disabled. Full native reconciliation happens on invalidation, not each settled entry. Neither multiple models agreeing nor an unmeasured performance estimate is treated as validation. Remaining risk: a whole-file native edit that produces no watcher invalidation while stream remains apparently healthy; implementation must test that detection/reconciliation boundary, and report the limit if the daemon cannot observe the edit.
