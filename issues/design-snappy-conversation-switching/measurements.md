# Evidence and reproduction (2026-10-02)

Synthetic Linux lab, production bundle (`./scripts/lab.sh start`), Playwright Chromium headless in a fresh synthetic Alice profile; no real browser or credentials. Revision at start `bc92625`. From repo root: `PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/ms-playwright" node issues/design-snappy-conversation-switching/measure-lab.mjs` (committed reproduction; a second run gave 102, 117, 99, 116 ms). After fake login, four SPA clicks between two **read-only native** conversations: click to history response + two animation frames took **108, 117, 100, 116 ms**; each caused **one history GET** (plus no other `/api/v1/` request in this short sample). These are not controlled `BrowserConversation` routes. The initial experiment mistakenly used full `page.goto` and waited for a history response *after* it had arrived, yielding ~5.3 s timeout artifacts: excluded. A controlled synthetic conversation was created in the lab via `Aloita uusi Pi-keskustelu`; full reload took 187 ms locally with snapshot, onboarding, conversation listing, status, history and events requests. Its send trace included repeated status/history reads; five captured history bodies in that single fake-Pi turn were 263, 263, 833, 833, 833 bytes. The controlled test used a full reload, **not** a controlled SPA A↔B switch; therefore the request count for that exact journey is a code-derived 2 HTTP reads (status + history) plus a fresh EventSource from `useConversation.ts`, not a measured controlled-switch count. Cold/deep network p95 on a real server is not established by this lab. No assertion that 100 ms is WAN latency.

Size-only read of own `~/.pi/agent/sessions` (private contents never copied): 313 JSONL files, total 313,961,781 B; file p50 507,095 B, p90 2,435,931 B, max 13,878,675 B. For first 200 files under 32 MiB, 39,382 lines: raw line p50 2,609 B, p90 8,056 B, p99 47,730 B. These are **raw Pi lines**, not browser entries: the reader filters, transforms and caps inline content (256 KiB/page, 25 requested by browser). Synthetic checked-in native fixture `test/fixtures/native/pi-events.redacted.jsonl` is 227 B/3 lines; richer invented lab histories come from `test/browser-host/lab.go:seedLab`; fake Pi's turn shape is `test/browser-host/fakepi.go`.

`simulate.py` generates representative JSON wire frames following `internal/daemon/events_linux.go:appendLocked` and the 50 ms coalescing rule; sample 120-character delta = 587 B SSE, settled entry with 2,609 B text (own raw median used as an explicit *proxy*, not an observed browser entry) = 3,180 B SSE. Heartbeat = 13 B / 20 s. Production entries may be shorter, inline-truncated or far larger; these are sensitivity inputs. Assumed typical: one writer, 4 deltas/s, 0.1 settled entries/s; heavy: eight writers, 20 deltas/s and one entry/s **each**, deliberately at the 50 ms coalescing ceiling. At the 128-frame journal limit heavy use may exhaust replay in under a second; uninterrupted streams still deliver frames. CPU 0.1 ms/event and 3× heap expansion are sizing hypotheses, *not browser profiler measurements*. SSE payload calculations exclude TLS/IP framing and gateway request authorization work. The stream exists already; A reduces reconnects, it does not create eight separate streams. Browser CPU/render frame target remains to be verified with an implemented virtualized window.

Current `history_linux.go` reads the selected file (bounded 32 MiB), lists entries from the **oldest** by `after`, page limit max 200 (browser 25); it has no tail-first or backward cursor. `status.native_revision` is a size/mtime hint, while history `native_revision` is a hash of the file; they are **not comparable**. A new tail-first/backward paging contract is part of the recommendation. Both baseline lab journeys are fast enough to be tolerable cold opens, not to satisfy zero-network recent switching.

Run simulation: `python3 issues/design-snappy-conversation-switching/simulate.py > issues/design-snappy-conversation-switching/simulation-output.txt`. Results are estimates, not a benchmark or a promise of 16 ms on long lists.
