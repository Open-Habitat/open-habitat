# Offer card thumbnails download the full image

## Description

Jari 8.11.2026, test server (`evidence/jari-2026-11-08-thumbs.png`): a folder
offer *5 isoa testikuvaa (yhteensä 129 MiB)* shows five thumbnails that take
very long to load; three were still half drawn. The thumbnails appear to load
each whole image file (~26 MiB) and scale it in the browser. A thumbnail must
be a small version of the image, not the full file.

Fix: the host serves a small, bounded thumbnail (e.g. longest side 256–320 px
at device scale 2, JPEG/WebP, a few tens of KiB) for image file and folder
offers and attachment previews, generated by the daemon as the person,
cached only where a cache is justified (prefer generating on request with a
bounded decode, or a cache next to the offer's frozen copy that is removed
with it; no new shared store). Bound decode cost: refuse or fall back to an
icon for images whose pixel dimensions exceed a limit (decompression bombs),
with a time and memory bound. Formats at least JPEG, PNG, GIF and WebP (Go
`image` plus `golang.org/x/image` if needed; record any new dependency).
The browser requests the thumbnail route, lazy-loads offscreen ones, and
opens the full image only when the item is opened. Check every place that
shows image thumbnails (file offer cards, folder offers, attachments, the file
panel).

## Acceptance Criteria

- [ ] A folder offer of five 26 MiB images shows thumbnails after transferring only small thumbnails (measure bytes in a browser spec).
- [ ] Oversized or malformed images fall back to an icon without exhausting memory.
- [ ] Touched Go, contracts, web and browser specs green; `KOKEILTAVAA.md` line.
