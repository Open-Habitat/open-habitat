# Terminal Pi writes across browser views

A daemon-side inotify watcher observes the mapped user's Pi session tree and publishes coalesced session-scoped invalidations through the existing per-user journal. It watches the owned, non-symlink ancestor chain for directories created after login and registers session subdirectories without following symlinks. On an identifiable JSONL write it reads only Pi's bounded header to select the agent; unknown paths and directory changes invalidate the whole snapshot. Native Pi files, read by the existing guarded history endpoint, remain the sole durable history source. A changed file is an observation hint, not a second cache or an authorization decision.

An external append causes each subscribed browser view to refresh the native window; native keys join overlapping journal events and history pages. Daemon-controlled Pi continues publishing typed live and saved entries; a watcher notification for the same file can cause a history reconciliation but cannot produce a second row with the same native key. Session-scoped hints avoid forcing unrelated cached histories in every tab to reload. If the watcher cannot start, loses its queue or encounters a directory error, it publishes an invalidation; queue overflow rebuilds and continues, while unrecoverable failure leaves native reads functional. Read-only warm navigation revalidates cached history even without watcher notifications. Controlled warm views remain cached and rely on their controller/journal path.

The alternative was a browser-side periodic check. That would multiply native reads and timers by open tab count and make update delay depend on each browser's interval. A single daemon watcher publishes one hint to all connected views, and the journal already handles replay, reconnect and gaps. For simultaneous terminal/browser use, provisional typed controller events and file observations may arrive in either order; saved native entry keys, not text matching or event timing, determine identity. Native reads retain their owner, revision, and ancestry guards. Snapshot race recovery frames are replayable but do not themselves increment the native-change generation, preventing overlapping browsers from sustaining a self-triggered resnapshot loop.
