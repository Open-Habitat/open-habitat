# History control result

The daemon now scans `/proc` on demand as the person's own nonroot UID. It checks ownership of each numeric process directory **before** opening its command line, cwd or descriptors; a different UID's process is skipped. For a Pi process, an open descriptor referring to the same native session inode, or an explicit `--session` path, means a writer is present. An unidentifiable Pi in that workspace, an unreadable own-UID process, or a failed scan means **unknown**, never permission to start another browser writer. The browser ownership lock still fences browser-launched Pi across daemon restarts. The census is repeated during continue, archive and retitle admission, not cached between requests. Restoring an archived item changes only presentation, so the mere presence of a terminal Pi does not block it when native history is settled; archiving still fails closed on an observed or undecidable writer. The browser's read-only history view probes eligibility separately, and a positive probe never reserves continuation: POST proves it again under the fence. Terminal-origin history stays read-only for sending, but settled history can be archived or renamed by a short-lived native Pi RPC child.

This is a Linux process observation, not a cross-client lock. A terminal Pi started after the scan does not honor the browser fence and could race admission. A Pi launched under an unrecognised executable name without an open JSONL descriptor or explicit session argument can escape identification (including from another directory). Standard Pi launcher and bundled entrypoint arguments are recognised; own-UID processes with the session inode open are detected even when they are not recognised as Pi. The permanently ptrace-restricted same-UID system services (`systemd --user`, `sd-pam`, `sshd-session`, `ssh-agent`) are excluded by their fixed command names so that they do not make every conversation permanently unknown. Such terminal behavior cannot be conclusively excluded with `/proc` alone; the daemon conservatively blocks ambiguous same-workspace Pi and inaccessible own-UID processes, but an observed absence is not an atomic promise that another process will not start. No root helper or cross-user process inspection was introduced.

The first independent review (Claude Fable 5.1) found ordinary-workspace false unknowns from other controlled Pi sessions, idle browser archiving regression, per-session `/proc` scan cost, global retitle permit hold, runtime-nil panic, unrecognised launcher limits, a transient retitle writer, stale UI proof and a duplicate-ID probe bug. The implementation was revised: skip only current daemon-owned PIDs (never an orphan from an earlier daemon), keep idle archiving, scan once per snapshot, generate outside the admission permit and re-check the native revision, guard runtime and reap the temporary child before response, read inode descriptors even for unrecognised launchers, guard async proof and count duplicate IDs. The launcher blind spot and terminal start-after-scan race remain explicit detection limits, not claimed to be solved by the tests.

The final independent verifier and the full clean gate are reported in the Taskfleet closure; their result is tied to the committed tree, so this issue evidence does not claim a future gate receipt in advance.
