# Synthetic resilience UI inspection

Not yet reviewed by Jari. Screenshots are from the disposable HTTPS lab (desktop 1440 × 900, narrow 390 × 900), not a live server or distinct-UID proof. `screenshots/error-before.png` and `screenshots/missing-before.png` are the first pass after the initial copy/retry work. `error-after.png`, `missing-after.png`, `empty-after.png`, `partial-after.png` and `ready-narrow.png` follow the second pass. No real identities or browser profile were used.

The first pass showed the same connection error twice (banner and main notice) and exposed “Lähdettä ei löydy” as if the reader knew what a source was. The second pass leaves one clear error with a retry button and names the missing workspace folder. Empty means no visible workspaces were found in a confirmed observation; partial says the list is incomplete rather than empty. The narrow view leaves the account action and workspace cards reachable. The warning for a failed read does not reproduce host response bodies.

Lab scenarios inspected through `/fixture/scenario?value=`: `empty`, `missing`, `error`, `partial`, `malformed`, `oversize`, `delay`, `native-error`, `foreign`, `pi-blocked`, plus `ready` at narrow width. Malformed, oversize and foreign responses show the same generic unavailable state, with no host content exposed. Delay shows loading before the eventual observation. `native-error` and `pi-blocked` lead to the first-use/onboarding flow, whose details are owned by that slice. Browser regression checks also cover recovery via button and the online event, authenticated expiry and same-tab identity switching in existing suites. A server that is stopped before the document loads can only show the browser's own network error; an already open tab can retry after the server comes back. This lab inspection does not establish what a real Pi restart does to running work.

The browser/host regression uses one synthetic host with invented Alice and Bob on same-UID sockets. No conclusion about separate Linux UIDs, production reliability or visual acceptance follows from these images. The conversation view is outside this edit; its error states remain with the concurrent conversation worker.
