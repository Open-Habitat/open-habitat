## Delivered

The daemon discovers Pi v3 JSONL by bounded header reads in the mapped user's own home. Only a header's exact `cwd` matching a confirmed immediate workspace associates a conversation; moved cwd is not guessed. `pi:<sessionId>` remains the native identity, `entry_key` the Pi entry ID, and the active append-tree leaf determines display order (abandoned branches are not silently interleaved). The gateway accepts only authenticated TLS same-host GETs, chooses the mapped UDS/UID, constructs fresh headers, checks peer credentials and bounds responses. Neither opening nor paging starts/resumes a Pi process, writes history or creates a history store. Snapshot reports `process: unknown`, `control: read_only`, `activity: unknown`. Browser routes use production rail/timeline/message/tool/code/unknown components; all native text is rendered as escaped plain text, not executed Markdown/HTML. Read-only status is visible in header and notice. Opaque revision-bound continuation rereads only the target file, never a copied history. Per-page cap is 200 entries and 256 KiB of inline UTF-8; each entry/chunk is at most 65,536 UTF-8 bytes on a codepoint boundary. Frontend requests 25 entries at a time and exposes explicit continuation. An append between pages preserves stable entry keys and displays a source-updated notice.

Review assessment is recorded in local `history/review-build-history-view.md` and `history/assessment-build-history-view.{json,md}`; no unaddressed finding passed the unlaned intake filing bar.
