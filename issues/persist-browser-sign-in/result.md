# Result: durable browser sign-in

Implemented in `ebc757b`, `5ae5b24`, `db73580`, `a0e66a3`, `4c1604b`, `54d0dcc` and `09824e4`. The gateway persists sessions at `/var/lib/native-agent-host-gateway/sessions.json` under its private systemd StateDirectory. The cookie contains a random 32-byte secret; the file holds its SHA-256 digest, broker-authorized Unix route, Access email binding, CSRF secret, profile and expiry times, not OAuth or native credentials. Atomic replacement, file sync and directory sync happen before a successful login, logout, profile update or operator revocation is acknowledged. A missing state file starts empty; at startup an unreadable or malformed state file discards all prior cookies, allowing a new OAuth login to replace it. A missing live file invalidates in-memory sessions before new login can publish a record. The file owner and mode are checked before restoring or accepting an active session; the pending OAuth flows remain in memory and are checked against the revocation serial as before.

## Decisions for review

- **90 days of inactivity, 365 days maximum from sign-in.** A person opening the host every few weeks or months remains signed in; an abandoned browser eventually expires, and a stolen cookie cannot renew indefinitely. The idle deadline advances after a day of activity rather than every request; the absolute limit also caps browser cookie expiry. The native GitHub disconnect freshness gate remains five minutes since the original OAuth login.
- **Store failure.** A missing file means all prior sessions are forgotten; an unusable startup file invalidates all old cookies; a fresh authenticated login replaces it atomically. A missing or incorrectly permissioned live file also clears cached sessions. An unwritable state directory still prevents a successful login. Disk errors during mutation return failure and never acknowledge logout or revocation before the replacement has been made. The file is limited to 4 MiB at write time so it cannot exceed the loader's bound after restart. The `sysusers.d` template already declares the gateway account; `systemd/` adds its private StateDirectory and `tmpfiles.d/` creates the same directory with gateway ownership and mode 0700.

## Deployment handoff

Do not deploy in this worker. The stint's final release must include the updated gateway service and tmpfiles template and use Fleetrepo's landed successor installer; apply `StateDirectory=native-agent-host-gateway` and `StateDirectoryMode=0700` before starting the new gateway binary. Verify `/var/lib/native-agent-host-gateway` is gateway-owned 0700 and survives release switching, then sign in on the test server, restart gateway, reopen browser and verify the session remains. Verify logout and `revoke subject` deny the old cookie after restart. The new version cannot preserve sessions created by the old in-memory gateway, so the first upgrade requires one sign-in; subsequent upgrades preserve them.
