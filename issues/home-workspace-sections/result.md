# Workspace-sections home: implementation and evidence

## Host and browser decisions

- The recap is the existing native `conversation-recap` Pi history entry. The browser uses the same validated `readRecap` GET as the recap above the composer, per displayed card. The existing native agent observation token changes with the session JSONL revision; only that card re-reads its recap when its native history changes. The previous text remains visible while the read is pending. There is no local recap registry or cross-snapshot cache. An old recap remains verbatim and is marked `uusia viestejä` when its `through` differs from `latest_message`. No recap is synthesized. An unanswered read says it failed rather than claiming a newly finished recap.
- Branch, dirty-file count and a credential-free GitHub owner/repo are bounded native Git reads from the daemon's pinned workspace fd, running as its Unix user. The optional summary exists only inside a snapshot; a failed or racy read stays unknown. Git remote URLs themselves never cross the contract. Existing remote classification receives its original 2-second whole-catalog budget first; the optional Git summary receives a separate 1.5-second catalog budget, so a slow status cannot starve remote classification. Dirty count is porcelain `-z`, with rename/copy second paths skipped. `github_repo` only appears for strict canonical GitHub SSH/HTTPS origin forms without userinfo.
- New directory uses the existing `POST /api/v1/workspaces` create action with source observation token and `git: true`; the daemon validates the single directory name, pins `~/src`, creates the directory as the mapped user, writes its ID and runs Git init. Clone uses the existing validated GitHub clone endpoint, which also reserves the destination under that user's `~/src`. The UI never sends an arbitrary path or UID. An already-open creation dialog disables submission when the connection becomes stale, and a pending write cannot be dismissed until its outcome is known. A lost or failed write reply is not retried automatically; the UI refreshes discovery and tells the user to check before another attempt.
- Only home receives the new grouping. Workspace pages retain their own conversation list and management controls. `Piilota etusivulta` is absent, and delete is disabled with its recovery prerequisite. The root route now redirects to `/workspaces`, the actual home, rather than arbitrarily picking the first workspace.
