# Result: provision first source directory

The root executor's `home` phase now creates `src` inside the just-created mapped home, through a no-follow directory descriptor. The new inode is chowned through its descriptor to the mapped UID/GID, and the home and source inodes, 0700 modes and absence of POSIX ACLs are checked. A safe existing source is accepted by the helper without mutating it; symlinks, unsafe existing entries and displaced inodes fail closed. The journal still blocks interrupted provisioning: this change does not implement recovery of a partially created account/home or repair a partial root-owned source. A subsequent operator recovery must follow the existing JIT policy.

`Verify` intentionally checks the mapped home but not `src`: after provisioning, user changes or deletion must reach daemon discovery, which distinguishes `source absent` from an empty workspace list. The gateway has no home access. The first route is published only after the `home` phase succeeds and the remaining phases and verification complete; no successful new provisioning can omit source creation absent later mutation by its owner.

Synthetic Linux fixture tests use disposable test directories (not `/home`), current test UID/GID, and no NSS/account creation. They exercise first creation, exact-mode safe repeat, pre/post-provision absence at the source helper, unsafe mode, wrong identity, symlinked home/source and replacement source, non-directory, and a partially created wrong-mode source. Wrong-owner source inode with actual chown is exercised only when tests run as root; non-root tests establish owner mismatch by testing against a different synthetic UID. No live host or deployment was touched.
