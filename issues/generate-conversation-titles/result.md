# Conversation titles — implementation evidence

Pi 0.85.1 has `set_session_name` in RPC (`dist/modes/rpc/rpc-mode.js`) and `ModelRuntime.completeSimple` in `dist/core/model-runtime.js`. It has no automatic title generation in the inspected RPC or session implementation. The daemon reads the latest native `session_info.name` from the session JSONL; when absent it still derives a first-prompt fallback. The controller writes through the owned Pi RPC child, never by editing history. Only browser-owned conversations admit regeneration; terminal-origin names are display-only.

The independent model request uses the mapped person's selected Pi installation and Pi's own configured credentials/model runtime, with no tools or agent session. It ranks available text models by input + output token price, preferring a non-reasoning model on price ties, chooses the cheapest, and declines when none is available. A user's only configured text model may be reasoning-capable; treating that capability as a disqualification would make generation unavailable for ordinary Pi accounts. Cost is a ranking, not a spending guarantee. Input is at most 4096 UTF-8 bytes from the first accepted prompt or bounded first/third excerpts; output is capped at 48 tokens and must be one trimmed, control-free UTF-8 line of at most 160 bytes. The subprocess has a 15-second deadline; the correlated name write has a 4-second deadline. Both are independent of sending and reading. The prompt requests a concise title in the conversation's language, and treats the excerpt as data rather than instructions. A model may fail to comply; invalid output leaves the old name alone.

A first attempt starts after the first accepted turn settles, because pinned Pi buffers fresh sessions until its first assistant message; starting at prompt acknowledgement cannot find a native file to check. One refinement follows the third accepted turn's settlement. The native name is checked both before and after the model call, and the controller serializes title requests per owned session. Native file scanning and name RPC run outside the controller's global mutex so a model call cannot stall conversation event drains. A later turn does not invalidate a name derived from the first; the native name precondition protects against stale user edits. An external/native/user-chosen name is never replaced by an automatic attempt; explicit regeneration can replace it and reports model failure to the browser. Continued browser-owned sessions recover a bounded first prompt for explicit regeneration without restarting the automatic schedule. The only remembered name is a transient precondition in this controller incarnation, not a durable title store.
