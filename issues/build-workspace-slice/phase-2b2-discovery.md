# Phase 2B2: bounded mapped-user workspace discovery

This phase adds only the Linux daemon's internal, fresh `Discover(trusted transport.Config)` observation. It validates the effective UID, OS account, configured home and other daemon mapping fields through the transport's existing trusted-config check. It never accepts a browser path, opens a browser route, reads a real user home in tests, caches observations, or returns absolute paths. The parent issue remains **in-progress** with all acceptance boxes unchanged.

The source root is opened beneath the trusted home descriptor via `openat2`; the home is opened below `/` without symlink or magic-link traversal (a separate filesystem for home is permitted). Source, children, annotation and Git hint use `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_MAGICLINKS|RESOLVE_NO_XDEV` and `O_NOFOLLOW`. Directory/file identity is checked across openings. Discovery reads at most 513 source entries (512 admitted), at most 4 KiB of annotation and 1 KiB of `.git` indirection, and rejects non-regular metadata without blocking on FIFOs. No descriptors remain in the model. Entries sort by raw UTF-8 filename bytes; invalid UTF-8 names and over-limit listings report partial instead of silently disappearing. Files and symlinks are excluded. A missing source, empty source, source error, and per-entry partial are distinct states. Child/stat/read/replacement errors remain generic per-entry facts, with no absolute path or underlying error string. Source replacement during enumeration reports partial.

An absent annotation does not remove a workspace. Present annotation accepts only the exact v1 fields, the schema's `ws_` ID grammar and bounded display name, with no duplicate/unknown/trailing JSON. Invalid, unreadable, symlinked or replaced metadata produces an error fact. A `.git` directory marks a main worktree. A bounded, strict `gitdir: ...\n` hint marks a linked worktree only when its target can be opened within the source descriptor or child descriptor without escapes or mount crossing. Typical linked Git pointers outside `~/src` remain `unknown`/partial rather than being followed. No repository content is read. The hint is not proof of Git integrity or authority for future writes.

## Focused security review

Reviewed trusted config versus request data, descriptor roots and openat2 flags, mount/symlink and `..` escapes, readdir type/identity races, FIFO blocking, metadata replacement, JSON duplicate/unknown/trailing fields, bounded reads and redaction. Corrected the initial root-open issue (absolute path with `RESOLVE_BENEATH`), `ReadDir` file-wrapper descriptor ownership, `DT_UNKNOWN` omission, metadata-file replacement checks, and FIFO blocking during the pass. Source and child replacement injections, mount/inaccessibility injections, metadata and source symlinks, linked hints, malformed JSON and max-entry behavior are exercised by synthetic-home tests. Directory enumeration is not an atomic filesystem snapshot; callers must reobserve before mutation. A same-inode in-place concurrent rewrite that preserves the observed stat timestamps is not proven immutable, so discovery cannot be used as mutation authority.
