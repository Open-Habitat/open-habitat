# Phase 2A correction: HTTP/1.1 native token handoff (not workspace delivery)

This correction supersedes the custom four-byte length framing described in the original phase 2A result at revision `30b9dc0`. ADR 0003 requires **HTTP/1.1 over one systemd-created Unix socket per user**. The corrected internal endpoint is `POST /internal/v1/native-credentials/github`, mounted on the daemon's shared HTTP ServeMux. It is not a browser API. `daemon.ServeHTTP` accepts the pre-opened listener and a caller-supplied mux; phase 2B can add workspace routes to that mux without a second socket. The existing `ServeHandoff` wrapper remains for the phase 2A entry point. No daemon CLI activation or native `gh` consumer exists yet; nil consumers fail closed.

A single callback attempt dials the mapped Unix path once, checks the connected `SO_PEERCRED` UID before writing, sends one HTTP/1.1 POST with `Connection: close` and a bounded JSON body, and reads only one bounded response. It uses no HTTP transport, proxy, redirect, retry or TCP fallback. Only an exact HTTP/1.1 `204 No Content` with no framed or extra body and a clean EOF counts as success. All errors returned to the gateway are generic. No token or native error text is returned by the daemon. The server checks the UID on each accepted AF_UNIX connection before admitting it to HTTP, installs verified peer context on that connection, and requires the context again at the endpoint; browser headers cannot grant access. It caps concurrent HTTP connections at 64, headers at 2048 bytes, request bodies at 8192 bytes, token at 4096 bytes, responses at 3072 bytes, deadlines at five seconds, and nonces at 4096. Equal duplicate Content-Length headers (normalized by Go before handlers run), mixed transfer framing, chunking, unknown or duplicate JSON keys, trailing JSON and wrong method/path/query/media type are rejected before consumption. Nonces are spent before consumer invocation, including failure, and capacity exhaustion fails closed. Systemd remains the socket creator; the server never binds or unlinks it. Configuration, effective UID, mapped numeric subject and user/home/socket checks remain intact.

## Focused review

Compared the implementation directly with ADR 0003's HTTP/1.1 and single-socket decision. Examined peer-context binding across the guarded listener and ServeMux, HTTP request smuggling through normalized duplicate Content-Length and transfer framing, retry/redirect/proxy avoidance, EOF on 204 responses and token/native-error redaction. The first pass found Go's HTTP parser normalizes equal duplicate Content-Length and `bufio.Reader` can hold a second response unseen by a direct socket read; both were corrected with bounded pre-parser wire-header inspection and EOF from the same buffered reader. Real AF_UNIX tests exercise these cases, wrong peer, wrong listener, symlink, mapping, malformed requests, replay, failure, capacity, timeouts and response limits. The kernel peer check remains the source of authority, never an HTTP identity header. This is not a full OAuth or native `gh` review.
