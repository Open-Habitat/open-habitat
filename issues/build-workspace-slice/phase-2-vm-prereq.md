# Phase 2 prerequisite: disposable systemd fixture

This is an **environment-only** proof for the two-UID VM prerequisite, not the gateway→daemon product route or completion of the parent issue. `build-workspace-slice` remains `in-progress`; no acceptance box is checked. Phase 2 still needs the real routed product implementation and phase 3 needs browser/visual acceptance.

## Boundary

`scripts/vm-test.sh self-test --json` stays offline, fast and boot-free. The separate explicit `systemd-self-test --json` validates YAML against the installed cloud-init schema and PyYAML inside a disposable rootless Podman tool image, verifies the image SHA-256 before any guest access, creates a private cloud-init seed and qcow2 overlay, then launches x86_64 QEMU under TCG with network disabled and no host shares. The base tool manifest is an amd64 Ubuntu 24.04 digest; `test/vm/Containerfile` pins the explicit tool packages. Podman storage is the only host-side runtime dependency; there is no host QEMU/cloud-localds install, sudo, KVM, Fleetrepo change or persistent VM. The cached public Ubuntu image is repository-local and checked on every run. Guest markers are synthetic strings, not credentials.

The fixture checks PID 1 is systemd, UID 21001/21002/21003, agent homes mode 0700 and marker files mode 0600, two mode-0600 per-user sockets owned by the mapped users, actual socket activation and UID-specific responses, and kernel permission denials for cross-user marker reads and route connects. The guest emits one JSON `VM_PROOF` line and powers down. Nothing here asserts a native-agent-host listener, OAuth, GitHub CLI, browser or a real gateway-to-daemon route.
