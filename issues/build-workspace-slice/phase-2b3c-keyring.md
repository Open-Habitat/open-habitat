# Phase 2B3c: native `gh` keyring metadata attestation (not workspace delivery)

Product revision: `b8cfc116e7b6615efc7c66f319a78d88e39c08ed` (initial implementation `6842e91bf32a4dc6eaf03732d0e6d40272242410` and focused security corrections). Production `daemon.NewNativeHandoff` now supplies a Linux Secret Service evidence provider. After `gh auth status` and `gh api user` verify the exact numeric mapped ID and a validated GitHub login, the adapter asks about that **login**, not the numeric subject. The verified HTTPS protocol, Git helper and discarded-output credential probe remain required. The fallback protected-file verification is unchanged: an existing unsafe plaintext file blocks keyring success, and a valid protected file wins deterministically if both evidence sources exist. No keyring evidence is inferred from missing plaintext or `gh auth status`.

## Pinned source compatibility and bus protocol

- [gh v2.46.0 `internal/config/config.go` at `b54f7a3bde50df3c31fdd68b638a0c0378a0ad58`](https://github.com/cli/cli/blob/b54f7a3bde50df3c31fdd68b638a0c0378a0ad58/internal/config/config.go): `keyringServiceName` returns `gh:` + hostname (lines 477–479); `Login` sets keyring with the username and falls back to the `oauth_token` file when Set fails (lines 319–355). `TokenFromKeyringForUser` calls Get with that username (lines 266–277).
- [zalando/go-keyring v0.2.4 `keyring_unix.go` at `987647a77244da26198ed51b2d8a29ccc11bceee`](https://github.com/zalando/go-keyring/blob/987647a77244da26198ed51b2d8a29ccc11bceee/keyring_unix.go): Set uses exactly `username` and `service`; Get chooses the login collection (or default alias), calls Unlock, searches by those attributes, then retrieves the secret. [Its Secret Service implementation](https://github.com/zalando/go-keyring/blob/987647a77244da26198ed51b2d8a29ccc11bceee/secret_service/secret_service.go) defines the bus destination `org.freedesktop.secrets`, root `/org/freedesktop/secrets`, `org.freedesktop.Secret.Collection.SearchItems`, and `org.freedesktop.Secret.Item.GetSecret`. We deliberately do **not** call Unlock, OpenSession, GetSecret, or Prompt.
- The sole new dependency is `github.com/godbus/dbus/v5 v5.1.0`, pinned in `go.mod`/`go.sum`, for typed D-Bus messages; importing go-keyring would expose token-retrieval operations and its prompt/unlock behavior. No CGO is needed.

The attestor uses the mapped user's `/run/user/<effective-uid>/bus`, requires the owned mode-0700 runtime directory and owned Unix socket, opens a private connection with a two-second deadline/cancellation close, authenticates with EXTERNAL (never the home-reading cookie fallback) and says Hello, then sends at most five metadata requests with `FlagNoAutoStart`: `Properties.Get(Service, Collections)`; `Properties.Get(Collection, Locked)`; `Collection.SearchItems({service: gh:github.com, username: <validated login>})`; `Properties.Get(Item, Locked)`; `Properties.Get(Item, Attributes)`. It uses `collection/login` when advertised, otherwise `aliases/default` as upstream does. It requires exactly one valid item, unlocked collection and item, and exactly two matching attributes. All errors are boolean denial, never returned bus/path/secret diagnostics. No shell or subprocess occurs in this attestor. An absent bus, locked service, malformed property/path, ambiguous item, timeout or canceled request fails closed.

## Focused security review and limits

Reviewed the pinned gh/go-keyring write/read keys and collection selection, spoofable session-bus address, multiple matches, locked collections/items, plaintext fallback precedence, TOCTOU, cancellation during authentication, and accidental secret reads. Fixed the original fallback's treatment of `Lstat` errors other than `ENOENT`: unreadable/unknown config paths now prevent keyring success. Restricted an item returned by the named login collection to that collection's path. Pinned D-Bus authentication to EXTERNAL; the library's default would also attempt COOKIE_SHA1, reading a home credential file. A malicious process **already running as this same UID** could impersonate the user's bus or mutate credentials concurrently; this is not a cross-UID proof or an atomic assertion of token value. The user session bus and filesystem permissions remain the trust boundary. The attestor never reads token bytes; upstream's Get still unlocks and reads tokens during actual credential use. An unavailable/locked user bus means keyring-only installation stays partial; protected-file fallback remains usable.

Tests use a fake metadata bus only (no real Secret Service), verifying exact positive attributes/login binding, absence/duplicates/wrong attributes, bad paths/properties, locked/error/cancel/timeout, bounded requests and no GetSecret call; native adapter tests also exercise unsafe plaintext precedence and protected-file priority. The production-constructor test verifies the provider is wired without connecting to a bus. No real credentials, host account, systemd, GitHub or Fleetrepo were changed.
