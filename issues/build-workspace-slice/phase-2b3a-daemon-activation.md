# Phase 2B3a: daemon socket activation (not workspace delivery)

The handoff-configured `daemon exec --config` now accepts only one systemd-style inherited fd 3. It requires the current `LISTEN_PID`, exactly one `LISTEN_FDS`, an optional supported daemon fd name, an AF_UNIX listening stream bound to the trusted configured pathname, and the mapped UID/socket mode checked by the transport. Before accepting, it probes the pathname against the actual listener, rejects replacement or a different socket, closes the original inherited descriptor after Go duplicates it with close-on-exec, and clears activation variables. It never binds, unlinks, chmods, chowns or falls back to TCP. Plain foundation daemon mode with no handoff remains separate.

The CLI constructs the native `gh` adapter from trusted mapped home/subject, then mounts its consumer with bounded health on one HTTP/1.1 mux and one listener. Native adapter failure stops startup; keyring-only storage still fails closed, while the existing protected-file verification remains available. There is no workspace route yet. Health contains no native metadata. The peer UID gate, connection cap, request timeouts and redacted handoff errors remain in force. Cancellation now waits for bounded HTTP graceful shutdown. Socket directory ownership and full systemd unit behavior are **not** proven by this synthetic test; phase 2C must test them in the disposable two-UID guest.

## Focused security review

Reviewed stale PID/count/name, TCP/datagram/non-listening fd confusion, descriptor ownership/CLOEXEC, socket pathname replacement, pre-accept failures, peer gate, timeout/shutdown, and token/native output leakage. Linux fd inode is not the pathname inode: a direct inode comparison would reject valid sockets, so a short randomized connect/accept challenge proves the current pathname reaches the listener before serving. A later privileged replacement is not prevented by that probe; host socket directory access and systemd ownership must enforce immutability. The synthetic integration uses real inherited AF_UNIX fd 3 and rejects bad envelope/type/path; transport tests cover replacement, shared health/handoff, peer denial and redaction. No live credentials, host user or real systemd units were touched.
