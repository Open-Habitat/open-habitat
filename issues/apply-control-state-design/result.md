## Decisions for review

- **Closure vs crash:** The host reports `confirmed_exited` without a cause; `/stop` interrupts a turn, not an agent lifecycle. Neither is displayed as *Valmis*. The pure presentation model accepts an explicit `intentionallyClosed` fact for when one exists, but current host observations remain *Tila ei tiedossa*. Treating an unknown exit as an intentional close would mislead users; no browser-local close marker is minted on a process stop.
- **New vs seen:** Validated `turn.settled` and `question.requested` event IDs and the status's `pending_question.request_id` create attention in the identity-scoped tab store. Opening that conversation in a visible tab marks the event seen; a subsequent event makes it new again; a new pending command or question resolution clears it. Status-only old settled turns are not retrospectively marked new. This is tab-local and not a durable cross-device read receipt. If the journal missed an event, an explicit pending question still appears as waiting; old replies with no observed event cannot claim unread status.
- **Waiting:** A live process with a known pending question displays *Odottaa*, including after it is seen. A live idle session with an observed reply/question marker also displays *Odottaa* after the visit. Idle alone, terminal history alone or an exit are not evidence of an open wait. A question supersedes a provisional accepted-turn label.
- **Attention and grouping:** The rail shows a new-attention count and badge; the return view ranks new attention ahead of working, then groups the top three under attention, positively working, waiting and other. A live process alone can still show a process-presence mark but not the *Työskentelee* activity label. Rows expose control and operation together visually (as well as in the accessible description); neither hides the other.
- **Control matrix:** The production Storybook story now includes button variants in rest/hover/pressed/focus, disabled/pending across variants, selected links, menu options, fields with error/required/disabled/read-only, textarea, checkboxes and radio selection/disabled. These are real controls; the story is an interaction surface, not a pixel-perfect proof for every draft frame. Existing pairs cover only a subset; no unmeasured state is claimed as visually signed off.

## Review and failure history

Self-review of the final code diff was proportionate for a palette/React presentation change without auth or daemon authority: checked source-of-fact boundaries, empty-send reason, dark contrast and narrow header. The browser axe and 200%-zoom cases plus the clean gate gave stronger primary evidence than a model opinion; no model review was invoked. Residual risk is incomplete visual parity and attention facts, not a claim that the design has been signed off.

The first clean gate failed 5/129 browser cases: a CSS token-edit mistake put dark overrides in the light selector (serious contrast failure), plus assertions pinned provisional wording/palette. Corrected tokens and assertions; five targeted tests passed. The second gate passed 129 ordinary browser cases but failed 2/15 lab cases: the crash assertion expected old uncertainty copy and two independent badges compressed a phone-width title to invisibility. Updated the wording check and allowed mobile header wrapping; the two focused lab cases and third clean gate passed. An attempted `test:e2e --grep @lab` found no tests because lab has its own Playwright config; reran with `playwright.lab.config.ts`, passing both targeted tests. An initial Storybook screenshot timed out because of the nested router and a draft-return phone capture timed out because draft state is driven by its controls, not `__dcSetProps`; both were corrected and all eight pairs captured. A local `test-web-fast.sh` run caught a CSS formatter error introduced by the Storybook state hook; formatted and reran the fast test successfully. These failed attempts did not certify the product and do not remain blocking after the final clean gate.
