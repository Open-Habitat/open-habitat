# Callback diagnostic boundary

The gateway emits JSONL `oauth_callback` events to stderr, using a server-generated 128-bit random attempt ID stored alongside the five-minute pending OAuth flow. A matching callback shares the start ID even when rejected; a callback without matching state gets an independent ID. No browser, provider or broker receives it. Unknown-flow callback logs have a process-wide 32-event burst and one-event-per-second refill, so anonymous requests cannot emit without bound. This budget affects diagnostics only; matched-flow events are never suppressed. The CLI injects its stderr writer and JSONL envelope (`schema_version`, `component`, `event`); these security events are always on, independent of `--verbose`. The event fields are fixed outcomes and reasons only; they contain no query values, identifiers, request URL, header, cookie, peer, provider error or identity. The callback still consumes state and clears the cookie before exact-shape validation, then checks the same predicates and returns the same response codes. Rejection classification is diagnostic only, after `exact()` rejects. A missing or expired flow is intentionally one reason; the in-memory sweep makes them indistinguishable. Multiple malformed conditions use a fixed priority (path/fragment, host, TLS, parse error, duplicate, missing/empty, extra) rather than suggesting unique root cause. A normal provider `error` shape is accepted by the shape check and then logged `provider_denied`.

**Support reference deferred.** A reference in the GET redirect would enter browser history, referrers and potentially third-party telemetry. The existing `auth_error` is a generic error code, not an ID. We retain generic responses and no browser-facing attempt ID. Operators can use a bounded time window and the restricted JSONL event stream; until a separate reviewed support channel exists, that is not guaranteed to correlate an individual browser report. Journal retention/access should be configured by the operator, not by this patch.

Synthetic tests cover accepted and rejected shapes, host/TLS, browser/expiry, replay and absence of secrets in captured JSONL. They are not a live request capture. The first-login incident remains open for Jari's fresh voluntary retest after an independently reviewed deployment; nothing here establishes what changed the original callback query, or that it was changed at all.
