## Implemented behavior

- Asetukset → Agentit → Pi includes Claude subscription sign-in. Native Claude Code alone creates its PKCE exchange, consumes the returned code and writes its native store. The daemon runs it as its own mapped nonroot UID with an explicit minimal environment and Claude's normal HOME-based defaults; no token is imported into Pi or copied by the host.
- The five-minute process lease is bound to the gateway-derived browser session and an attempt generation. Another session cannot read its URL, submit a code or cancel it. An old tab cannot submit to a replacement attempt. Restart loses only the lease, not native login. Cancellation returns uncertainty, not logout. Native errors/stdout and credential values are never returned; only a validated Claude URL and coarse status cross the schema. Code fields are cleared immediately, including after uncertain submission, with no automatic write retry.
- The shared picker carries `claude-bridge` provider-qualified identities through native default writes, per-conversation launch choice and continuation. Newest numeric Claude model per family is primary; older entries remain under the existing disclosure. Models are offline candidates, never an entitlement assertion or billable probe. Their observed outcomes derive from bounded native Pi history, separated from OpenAI identities.
- The daemon's Pi RPC startup explicitly loads the declared extension if present. The catalog uses pinned Pi's extension loader and provider registrations, not an invented Anthropic model table. Both paths tolerate an absent bridge during product-first deployment. Existing user Pi resources remain native. A Claude-only native login can satisfy initial Pi readiness, and first-use onboarding exposes the same sign-in component.
- Contracts live in `contracts/v1`, including the one-time code and lease schemas, updated provider enums, synthetic example and onboarding scenario; generated Go/TS fingerprints were regenerated. HTTP authority and semantics are documented in `docs/architecture/http-api.md`.

## Decisions for later review

1. **Use the SDK-supplied Claude executable, not another CLI install.** It supports native `auth login --claudeai` and `auth status --json`; the bridge already drives it. This avoids two independently versioned Claude binaries. Its Linux x64 path is a declared guest-runtime detail, not browser input; the whole runtime is covered by existing root-owned/nonwritable-tree validation and Fleetrepo integrity receipts.
2. **Optional runtime, explicit native activation on model selection.** Browser RPC and native catalog load the same trusted extension path. Merely installing it does not modify people's `settings.json` or enable unrelated tools. Explicitly selecting a Claude default registers the trusted extension path through Pi SettingsManager, preserving other extension preferences, so native SSH Pi can use that default without an extra `-e`. Plain terminal Pi can also load the same extension explicitly with `-e <runtime>/node_modules/pi-claude-bridge/src/index.ts`. Native model/thinking defaults are still written through Pi SettingsManager.
3. **Pin an internal loader seam to Pi 1.3.0.** Catalog discovery needs extension-registered model metadata but must not activate arbitrary user extensions or unrelated API-key shell resolvers. The helper imports Pi's exact-version `core/extensions/loader.js`, processes only the declared bridge's provider registrations and makes no model request. Real pinned-dependency tests guard this seam; it must be reconsidered with a Pi upgrade.
4. **Subscription status is sign-in presence, not entitlement.** Native `auth status --json` must report loggedIn and claude.ai; candidate availability does not establish billing plan access. Jari deliberately performs the actual sign-in and first Claude turn. No operator reuses his live credentials in tests.
5. **Keep the existing new-conversation model switch.** No in-flight session mutation or message replay was added. The bridge stays a Pi provider, so history, tool handling and ordinary controls remain Pi-owned. Live SSH/default agreement and signed-in turns remain manual acceptance steps in KOKEILTAVAA.md.
