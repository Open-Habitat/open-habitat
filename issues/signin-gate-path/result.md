# Gate path repair on the test guest

Fleetrepo commit `86dce87ba59a2ff03428305211c5d176d9b7e449` was pushed to main before installation. Its installers, preflight, policy helpers, tests, gate units and release checks now use `/usr/local/libexec/open-habitat-test-jit/`. A comparison of product `internal/` and `systemd/` absolute paths and unit names found no other product/Fleetrepo rename mismatch. Fleetrepo's 185 offline tests passed.

On `native-agent-host-test-nbg1` (`203.0.113.10`) via the pinned root SSH route, the two helper files staged from that commit matched the installed old copies (SHA-256 `2a5f291cdcfb67cdc6d03abc6c9c23bb60d603c86a88e41a98193d2d40d397e5` for `jit_policy.py`, `ee58db69e00861b290678dc11d42a94b7fbaf4539d2ce0d88c28d35074445103` for `jit_acl_prepare.py`). Both were installed root:root 0755 at the new path. The gate unit templates were checked against the previous installed versions and replaced from the approved new files (root:root 0644), followed by `systemctl daemon-reload`. The old directory was removed only after checking the new helper and effective unit; the old Python bytecode cache was also removed.

`systemctl show open-habitat-daemon@maintainer.socket --property=Requires,After` includes `open-habitat-jit-policy-gate@maintainer.service` in both fields. `systemctl show` on the gate instance reports `LoadState=loaded`, `User=root`, `Type=oneshot`, `RemainAfterExit=no` and exactly one `ExecStart` with `/usr/bin/python3 /usr/local/libexec/open-habitat-test-jit/jit_policy.py verify --phase activation --target daemon:maintainer --json` and `ignore_errors=no`; no other nonempty Exec* commands. A direct activation verification on the new path returned `status:verified`, `bindings:1`, `active:true`. The user's daemon socket remained inactive. No daemon start or simulated sign-in was performed.

The first property-check script falsely failed because it compared the parsed `ExecStart` value with a prefix that still included `ExecStart=`. The corrected read-only check passed before retiring the old directory. A subsequent `rmdir` found only an old `__pycache__/jit_policy.cpython-312.pyc`; it was inspected and removed before successfully removing the directory. These two operator hiccups did not alter the product gate's fail-closed behavior.
