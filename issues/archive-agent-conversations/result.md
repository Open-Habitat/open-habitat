# Result — conversation archive

Browser-owned Pi conversations can be archived after a verified idle turn or confirmed child exit, restored in their workspace and deliberately continued on the same native `pi:<sessionId>`. The daemon checks fully readable, settled native history, the discovered workspace and a fresh observation token before writing `archived_at` to the mapped user's XDG presentation state. The shared state-file writer serializes workspace visibility and archive updates; corrupt annotations are never overwritten. Terminal histories have no admitted archive path. Archived browser conversations cannot accept another browser send until restored. Restore starts no Pi process. Native JSONL is not moved or copied.

## Decisions for review

- The host does not know whether an independently detached tool finished after the daemon child exited. Archiving only tests its own idle/confirmed-exit state; the UI does not call Pi `abort` or treat `stop` acknowledgement as proof. Terminal history stays readable but not archivable.
- There is no archive-specific approved draft or `ArchiveDialog` contract. Confirmation uses the shared control language inline on the conversation; the archive appears on its workspace page, with a separate restore action. Jari's visual verdict remains pending after deployment.
- A lost archive response is shown as uncertain until snapshot refresh; a rejected stale request is shown as a confirmed conflict. Restore works after daemon restart even if the control handle is lost, but archive requires a live daemon handle. After restart the browser currently has no direct continuation control for that lost handle, although the backend has a browser-origin proof path. That discoverability gap is not a second history store or evidence of terminal control.
- Archive uses the already authenticated, CSRF-protected workspace POST route with a distinct `conversation_archive` action. The gateway's conversation route currently admits only enumerated actions and was owned by a concurrent worker; the daemon alone resolves native ownership. This is a workspace-scoped presentation annotation, not a new history store.
- A missing or unreadable archived native session makes the Pi-history source unknown rather than presenting a confirmed empty archive. Restore controls are disabled until the history is readable. Existing native-history read bounds still apply; large histories the host cannot fully read are not silently archived.

The review finder found a synthetic browser-host real-home path, fixed by routing the fixture workspace home; the independent verifier found a synthetic snapshot token-home mismatch, fixed and asserted. Optional model-performance upload failed because SSH access to alder was denied; review assessment and scores were saved locally, with that logging limitation disclosed to the caller.
