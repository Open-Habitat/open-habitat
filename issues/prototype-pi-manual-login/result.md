## Reproduction

From this repository's root (Node >=22.19, npm, git, public network access for source/dependencies):

```sh
bash issues/prototype-pi-manual-login/test-patch.sh
# Optional, only on a machine with the prior proof's precisely pinned installed artifact:
node issues/prove-pi-browser-auth/proof.mjs
issuectl doctor --json
```

The runner clones only the pinned tag into a disposable directory, checks HEAD and both package versions, applies the patch using `git apply --check` and `git apply`, uses a disposable HOME/agent directory/npm cache, runs `npm ci --ignore-scripts`, targeted Biome and two upstream Vitest files. It removes the clone and HOME on exit. No real credentials, browser, Pi history or user auth path are read. Test fetch is replaced with an allowlisted synthetic token response or a failing spy; no live provider request is made. A `Server.prototype.listen` throwing spy proves the manual-only branch never invokes `listen`; a port sentinel alone would not. Patch adds only an optional `AuthInteraction.manualOnlyBrowserOAuth` hint and the Codex-specific branch: no selection of device code, no listener, full raw redirect prefix plus parsed origin/path and exactly one nonempty `code` and matching `state`, no fragment/userinfo/extra params. Pi retains generation of state/PKCE, token exchange, credential storage and refresh. Without the hint, normal TUI `/login` remains on the original browser/device selection and callback/manual fallback path. The `ModelRuntime.login` → `Models.login` interaction spread forwards the optional property; installed ModelRuntime's synthetic native provider auth-path behavior is tested by the prior proof. No extension or RPC behavior is silently changed.

Observed in this run: runner **28 tests in 2 files passed**, including original native Codex OAuth tests; formatting passed. The prior proof passed its six synthetic checks: 0600 native credential file in disposable HOME, post-write sync failure can return an error with committed credential, and logout in one process does not fence an outstanding login in another. `issuectl doctor --json` succeeded. A monorepo-wide `tsgo --noEmit` attempt failed on missing generated `packages/ai/src/providers/data/*.json` in a fresh source checkout (including unrelated `getModel` type errors); the targeted patched files' Vitest transform and native tests passed. **Product `./scripts/ci-local.sh --clean --json` was not run** because no product source or browser/host contract changed. This is not a production build or live compatibility proof.

## Boundaries for the host

The interaction must be exposed only to the correctly mapped Unix UID and authenticated browser session; the option alone does not bind state to the browser session or prevent a different process holding the same native user's credentials from finishing a pending login after logout. The browser's loopback error/address-bar copy UX has not been tried with an actual user or OpenAI consent. The host must enforce its own one-shot attempt ownership, session/UID binding, deadlines, no URL/code logging anywhere in gateway/daemon, helper termination/join and unknown-after-write reconciliation. The manual branch sanitizes token-response and prompt-adapter errors; callers must not log the auth URL, pasted input, credentials or native error objects. An operation aborted after a token exchange or during native file storage may still have committed: re-read native status, never retry the code blindly. This patch does not establish entitlement, cross-UID peer binding, browser-session isolation, CSRF protection, or a production login architecture. Host security design still needs Jari's approval.
