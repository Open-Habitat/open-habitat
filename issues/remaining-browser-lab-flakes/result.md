# Result

## Root causes and changes

- **Composer queue:** the original gate on `da46fc2e` observed zero follow-ups. Holding Pi reproduced this while Pi was still working: the second message remained in the editor because Alt+Enter raced the preceding asynchronous send. The keyboard journey now waits for the steering event, cleared field and send availability before sending the follow-up. Its shared work helper also uses the existing `pi-visual-hold` and waits for the tool-start marker, so queue restoration, Escape and phone layout inspect a persistent native state. The completion/focus journey releases Pi only after preparing the draft and lost-status route.
- **Paging after recovery:** the fallback waited for `user-content`, which identifies a pending message, not the settled user message. It now waits for the actual native `Kierros 8` content; cursor exhaustion and oldest-message checks remain.
- **Buffered native replies:** Chromium repeatedly discarded CDP response bodies for worktree removal, title regeneration and archive, even with immediate `response.json()`. Title assertions now buffer the real reply through `route.fetch`; the workspace archive case uses the shared exact-receipt helper, which already buffers the real reply. No success body is invented.
- **Worktree cleanup:** Chromium intermittently discarded the CDP response body, even with an immediately awaited `response.json()`. The case buffers each real removal reply through `route.fetch` and fulfils the original response unchanged. Each step checks the reply before the next action or navigation. No mocked success is substituted, and all Git-result and visible-removal assertions remain.
- **Focus ring / idle-slot admission:** creation first mounts a local draft which the native composer replaces. The ring journey now waits for the native command palette before focusing and measuring the field. The idle-slot helper and the changed-identity/status journey wait at the same boundary before filling a native message or opening native status details; without that wait the message could be entered into the field being replaced and leave Send disabled.
- **Editor expansion / product focus race:** ordinary `workspace-editor.spec.ts:193` exposed focus scheduled before React had committed a hidden conversation's expansion. All expand-and-focus paths now use `showConversation`: already-visible fields focus immediately; hidden fields focus in a layout effect after the expansion commit. Review also reproduced a stale passive-listener window after continuous drag expansion: an old collapsed=true callback could queue focus against an already-expanded state. Frame-message and keyboard listeners now refresh in layout effects, matching the committed DOM before another browser event can arrive. A new regression holds animation callbacks pending and sends a valid editor-frame toggle; old code leaves focus in the iframe and fails. The existing browser shortcut/focus/selection assertions remain unchanged.
- **Provider layout:** axe and the other provider form could outlast the fake device helper's two-second lifetime, so a native poll correctly removed the old code before the layout case returned to it. The selected layout host now sets `BROWSER_HOST_HOLD_PI_DEVICE=1`: the real synthetic helper emits its code then stays pending until that host exits. All other cases retain the two-second completion behavior. No browser timers, native response fields, code/layout/axe assertions or deadlines change. Two clock-based attempts were abandoned: pausing before delivery stopped the initial poll (60 failed provider repetitions); pausing after delivery blocked axe's timers (12 failed provider repetitions). The final solution holds the helper, not the browser clock. With persistent codes, a focused run exposed three light-theme axe failures sampling the 120 ms selected-provider color transition; the final layout case uses reduced-motion media to audit settled colors without changing the palette or contrast assertions. Logs: `/var/tmp/flush-provider-title-{diagnostic,green,held}.log`; the corrected final focused run is `/var/tmp/flush-complete-focused.log`.
- **Stopped-history title / restart fixture:** a 409 after restart exposed that `/fixture/daemon-restart` only queued controller cancellation. The browser could reach its replacement while the old Pi still held a native ownership fence or was finishing a write. The fixture now calls guarded `FixtureShutdown` synchronously before replacing the controller and cancelling its context. The wrapper only acts on fixture controllers; no production shutdown behavior or HTTP contract changes. Title journeys also wait for the native composer and buffer live title replies. The 409 did not reproduce in 45 focused title cases; the asynchronous restart gap is directly visible in the source and is now removed rather than retried.
- **Archive helper receipt:** the worktree-agent journey found that the shared helper matched any POST to `/api/v1/workspaces`. A concurrent `worktree_list` reply could be accepted as archival success. Routing and receipt matching now both require `action: conversation_archive`; all callers retain their actual archive/removal checks.
- **Archive undo / product race:** response diagnostics proved `409 control_uncertain` came from the Pi-writer census, not an archive mutation/snapshot-order bug. Linux returns `ESRCH` when reading fields of a pinned `/proc` directory after its process exits. The census treated this ordinary process churn as an uncertain writer. Both single and batch Pi censuses now treat `ESRCH` like `ENOENT` for vanished process entries. A subsequent critical review proved empty cmdline is not exit proof: protecting argv memory can hide a live writer. Removed that pre-existing shortcut from the batch scan and rejected adding it to the single scan. Both use kernel Z/X task state as exit proof instead. Mutation guards, like workspace deletion, recheck once after the existing bounded settling wait when a census is unknown, refreshing owned-child facts. Persistent permission/opaque failures remain fail-closed; tests prove both transient exit settlement and persistent refusal, plus live matching descriptors with empty arguments. A real-process regression pins the directory, kills/reaps the child, then reads the pinned entry: it failed with `unknown` before the fix and passes after it. The browser case now checks the real archive reply before inspecting undo.

**Final verdict: zero failures in both required stress runs.** Lab ×5: **310 passed in 147 s**. Ordinary ×2: **604 passed, 6 opt-in capture skips in 258 s**. Fast web: **22 s**. Full daemon/browser-host race checks: **95 s**. All confirmed review findings are fixed.


No existing assertion was weakened, timeout raised or case removed. Native-content assertions remain; no UI-wording assertions were added. Temporary diagnostic response-code changes were restored before final verification.

## Review and limits

Self-review checked each test's asynchronous boundary and retained behavioral assertions. Focused independent census product review completed: `claude-fable-5-1` finder (323 s) and `gpt-6-astra` narrow UID/live-writer boundary verifier (56 s), no confirmed defects. The final census trusts kernel task exit state, not argument contents, and uses bounded settling only before re-observing an unknown mutation census.
