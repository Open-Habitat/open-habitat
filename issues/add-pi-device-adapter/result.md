# Pi device adapter: daemon + native helper delivered (2026-09-28)

**Revision:** `31101a4e1f7cf14ce01e5b5f2d521c85f541715b` (application code before this result/closure). Daemon-only walking slice; no gateway gate, wizard, browser API, deployment or real provider sign-in. The older blocked experiment is retained below as history, not the current outcome.

The mapped-UID `PiDevice` starts one attempt with a daemon-generated ownership ID, five-minute deadline and owner-only cancellation. It runs an embedded, bounded Node helper through the pinned Pi **0.85.1** `ModelRuntime.login('openai-codex','oauth',interaction)`, selects `device_code`, forwards only the fixed native verification URI/user code, and rechecks native status before reporting usable. Pi owns token exchange, native `auth.json` creation and refresh; no host credential writer or gateway token storage. Helper stderr is discarded, stdout is strictly framed/redacted, and losing the parent stdin pipe aborts Pi polling. Existing unsafe symlink/file mode/owner paths refuse to start instead of being followed or rewritten. Status is `missing`/`usable`/`unknown`; an empty OAuth access token is unknown. Pi's unrelated provider credential commands are not executed by runtime's create-time availability scan.

**Evidence:** `TMPDIR=/var/tmp ./scripts/ci-local.sh --clean --json` (with worktree-local Go 1.27.1 in PATH) passed on `31101a4` after 135s; `/var/tmp/pi-adapter-ci-final-01m3kzyb5k7kby20qtdxdqy3yf.log` ends in `{"status":"passed","clean":true}`. The closure tree at `e7c99a2` also passed the full clean gate (`/var/tmp/pi-adapter-ci-closure-retry-01m3kzyb5k7kby20qtdxdqy3yf.log`, `{"status":"passed","clean":true}`). Its first rerun failed in six unrelated Playwright design-system cases because the local Vite fixture server on port 4183 stopped responding mid-run (`net::ERR_CONNECTION_REFUSED`); the unmodified clean retry passed. An earlier pass at `6fffbbf` preceded final review fixes; the first attempted gate failed solely because `gofmt` modified an uncommitted test, and was corrected and rerun. Mandatory CI installs pinned Pi from `internal/daemon/pi-device-test/package-lock.json` and runs the synthetic Node suite; Go race tests cover attempt ownership, bad paths/HOME, cancellation during post-login status and child reaping. Node tests exercise real Pi 0.85.1 OAuth SDK with mocked fetch, native stored file mode 0600, redacted frames, empty access and parent-pipe interruption. A one-off rootless Podman `node:22-bookworm-slim` network-disabled test with actual disposable UIDs **12001/12002** and synthetic homes verified: A completed native login, B remained missing, B could not read A's auth file, and A's IPC had no refresh token. This proves synthetic container UID separation, not live-host isolation. A prior direct container attempt with stdin closed produced `unknown` and no credential; keeping the parent pipe open yielded the passing proof. No external OpenAI request, real HOME/SSH/browser, live host, or deployment was used.

**Independent final review and assessment:** `history/review-pi-device-final.md` and `history/assessment-pi-device-final.{json,md}` (gitignored local artifacts). Finder `gpt-6-astra` found three concrete defects: post-login cancellation lost authority, startup scanned unrelated provider credential commands, and empty OAuth access was marked usable. All were fixed in `31101a4`; independent `gemini-3.8-flash` rechecked the final diff and refuted all three in their fixed state. It also suggested three additional concerns; one was contradicted by Pi OAuth tests, one was speculative against a five-minute kill, and one framing edge is unreachable with the current bounded native events. No surviving review finding merits an intake issue; no issue was filed. `claude-fable-5-1` failed with exit 1 before output. The model-performance corpus helper also failed its SSH-to-self write on alder (`Permission denied (publickey,password)`); no client seat was attached for the documented reverse-channel workaround. These review-log failures did not prevent the independent security review or clean gate; no model output is attributed to the failed call.

**Limits:** This adapter is callable daemon code, not yet wired to a gateway/browser contract or installed Pi runtime on the test host. `usable` is a local native OAuth-resolution result, not a live OpenAI entitlement proof. The ordinary onboarding flow excludes independent terminal Pi login/logout during the attempt; no cross-process fence or revocation guarantee is claimed. A daemon crash after Pi's native commit but before confirmed status produces an interrupted/unknown attempt; a new daemon must call native Status. Existing terminal credentials and other providers are preserved.

# Earlier experiment: blocked security proof (2026-09-28)

**Outcome:** Not delivered, not deployed; no application code merged. The experimental daemon/Node candidate was deleted after security review rather than shipping a credential-handling placeholder. With Jari's authorization, this issue metadata and research report were harvested from the failed run into main; the retained worktree/branch has **not** been discarded. The issue remains in progress. Gateway gate, browser contract and wizard were not touched. No real OpenAI sign-in, native user home, browser profile, or live credential was used.

## Source and experiment

Inspected installed Pi `@earendil-works/pi-coding-agent` **0.85.1** (`docs/providers.md`, `docs/sdk.md`, `dist/core/model-runtime.js`, `dist/core/auth-storage.js`, `@earendil-works/pi-ai/dist/auth/oauth/openai-codex.js`, `dist/auth/resolve.js`), plus `issues/design-first-use-onboarding/plan.md` (its browser/manual-only recommendation is superseded by Jari's device-code decision), `docs/architecture.md` and `docs/interfaces.md`. Pi's `ModelRuntime.login('openai-codex','oauth',interaction)` can select `device_code` using the native `select` prompt. It emits `device_code` with a verification URI and user code, polls and exchanges through native Pi, and writes `openai-codex` OAuth to its own `auth.json`; it is not a Pi RPC `/login` and not an `openai` API key. `listCredentials` returns provider/type; `getAuth` can resolve/refresh, but returned credentials must never cross the UID boundary.

A temporary Go child supervisor and Node helper using this public runtime were built locally with a synthetic HTTP fetch replacement. Focused Go tests (`go test ./internal/daemon -run TestPiDevice -v`) passed two process/protocol cases. A synthetic Node test against installed Pi 0.85.1 (`PI_TEST_PACKAGE=<installed package> node --test internal/daemon/pi-device-helper.test.mjs`) passed a device-code exchange, native OAuth file creation with mode 0600 and absence of sampled secret values in IPC. Both were *candidate tests subsequently removed*, not CI coverage, not two distinct UIDs, not a live provider, and not a proof of cross-process isolation. Go 1.27.1 was provisioned only into this worktree's ignored `.tools` via `scripts/bootstrap-tools.sh`; no global Pi installation was changed.

## Independent security review and assessment

Independent `consult-llm --task review -m gpt-6-astra` reviewed the actual candidate Go/Node/test files with source attached. Review artifact: `/tmp/pi-device-review-01m3k7ak85b90d2gb3ry7xbg5m.txt` (local scratch; findings below stand alone). It additionally reproduced two credential-path problems with Pi 0.85.1 under disposable homes and mocked fetch. Assessment against candidate source and native Pi code:

| Finding | Confirmation / real-world likelihood | Disposition |
|---|---|---|
| Existing `auth.json` mode 0644 remains 0644 after Pi writes; Pi follows an `auth.json` symlink to a target outside the selected home. Candidate validated only home, not credential ancestors, ACLs or target. | **Confirmed by synthetic reproduction**, occasional where a pre-existing file/misconfigured home is unsafe; leaks or redirects real credentials. | Must fix with secure path/ownership/mode validation and two-UID tests before merge. |
| Daemon crash leaves orphaned Node device poller because Go context cancellation does not run after daemon SIGKILL; old process can commit after daemon replacement. | **Confirmed in code**, occasional during crash/restart. | Must implement and prove parent-death/cgroup or lifetime-pipe ownership before merge. |
| Synchronous `emit` callback blocks Go child reaping and per-UID mutex release even after timeout; recovery from callback panic can skip wait. | **Confirmed in code**, occasional under slow/disconnected client. | Must decouple bounded event delivery and make cleanup unconditional. |
| Native Pi login's post-poll credential commit can overwrite a newer terminal Pi login or restore auth after terminal logout; Pi file lock serializes writes but does not fence stale attempts. | **Confirmed in Pi source**, occasional with terminal and browser concurrent use; prior native proof in `issues/prove-pi-browser-auth/proof.mjs` exercises logout variant. | **Architecture/security dependency:** a Pi-native conditional commit/generation mechanism, or Jari's explicit acceptance of documented last-writer-wins semantics. Do not claim the daemon lock fences external native writers. |
| A scanner error on trailing oversized frame did not invalidate a prior success; two terminal `result` frames were accepted. | **Confirmed in candidate Go code**, rare unless child is faulty/compromised. | Straightforward strict framing fix in replacement candidate. |
| Tests had no actual two-UID proof; access-token sentinel was not the issued synthetic JWT; helper suite was optional/skipped by CI. | **Confirmed from test and CI source**, regular verification gap. | Require disposable two-UID integration, exact JWT/stderr scan and mandatory synthetic package test. |

The review is **not** independent confirmation of live OpenAI entitlement or host installation. No review finding was filed as a new unlaned issue: each is directly within this existing, unfinished issue's acceptance criteria. The test host was not touched.

## Next safe step

Agree the external Pi terminal-writer concurrency semantics with Jari. If last-writer-wins is unacceptable, obtain a reviewed Pi-native conditional-credential-commit facility before implementing the host adapter; do not substitute a host-side unlocked comparison or a second credential store. Then implement credential-path containment, parent-death cleanup, bounded IPC supervision and owner/session lifecycle with mandatory synthetic tests and a real disposable two-UID VM proof. Only after that run the full `./scripts/ci-local.sh --clean --json` and an independent review on the *final* diff; the candidate's passing focused tests do not clear this gate.
