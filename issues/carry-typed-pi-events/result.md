# Typed Pi events: initial history slice

This run is **not the completed issue**. Native history now projects ordered text, redacted-thinking markers, image type placeholders, and tool-call identities into bounded typed blocks, with the model, stop reason and tool-result association. The same projection travels in `history.entry` journal frames, and the browser renders the typed blocks from either source. The native session remains authoritative; paging, native keys and the existing full-text content endpoint remain in place. Unrecognized block payloads and unknown entry payloads are no longer echoed to the browser.

## Privacy selection

The projection explicitly excludes thinking signatures, provider diagnostics and response IDs, raw provider errors, deferred data, arbitrary extension `details` and `data`, tool arguments and image base64. These values may contain credentials, and a generic redact-by-key filter cannot safely establish that they are displayable. Redacted thinking does not include its text. Hidden custom messages in both native forms are omitted. The `unknown` marker names no unchecked payload. Visible extension message content, image data and safe argument access need a considered bounded content-read design before this can be called complete. The old flattened full-text content endpoint still exists and must be replaced along with its browser fallback before this issue can close.

## Continuation: bounded typed block reads (6c9d0be, 6bda850, e0a626c)

This is a further completed slice of the in-progress issue, not completion of the whole issue. The daemon now reads one selected native entry/block under the mapped user's daemon and authenticated gateway. A request names the agent, active native entry key, block index, exact native file revision, byte offset and a bounded limit. It re-reads Pi's native file and verifies active ancestry, UID/file stability and revision. UTF-8 text is sliced on codepoint boundaries (at most 64 KiB); supported base64 image data is sliced on quartet boundaries (at most 1 MiB). History pages and journal frames retain ordered typed previews, with history pages also capped by the serialized entry budget, rather than carrying long text, image data or arguments. The old `/api/v1/content/` handler, gateway route, browser fallback and contract fields are gone.

The browser reads long text and non-redacted thinking, image data, tool arguments, tool-result text/images, compaction/branch summaries and visible extension messages by selected block. Images of ordinary size assemble automatically after one explicit action, still through individually bounded requests. Larger ones retain a page control. Redacted thinking stays a marker; unknown blocks and entries expose no raw fields. Live `history.entry` frames carry the native revision needed for selecting a saved block before the next page refresh. The existing user-message and tool-row primitives render the new controls without duplicating long user text or describing a saved result as still running just because its preview was cut.

**Privacy selection:** persisted text and non-redacted thinking are displayable; thinking signatures and redacted text never are. Supported image MIME data is read only on request and rendered as a local inert image, not a remote URL. Tool-call arguments, saved tool-result content and result images are deliberately selectable by the owner on request, not carried in a page or journal frame; arguments can include credentials and are shown as inert text. Saved compaction/branch summaries and `display:true` extension content are selected by field. Hidden extension messages cannot be selected. Excluded: provider diagnostics, raw provider errors, response IDs, arbitrary tool/extension `details` and `data` metadata, unsupported image MIME, unknown block payloads, and unchecked extension hook/UI internals. These lack a reliable safe display interpretation and can contain credentials. Native files remain authoritative; no parallel content store is introduced.

## Continuation: typed live tool, command and lifecycle projection

This run extends the previous typed history, thinking and bounded block-read slices. Live `toolcall_delta` / `toolcall_end` preserve the assistant block index and call ID. Tool execution start/update/end carries the call ID, name, state, bounded argument preview and bounded text-only partial/final result preview. The browser joins those by call ID rather than creating a row per update; the final saved tool result replaces the corresponding provisional call and progress, while unrelated calls remain live. `bash_execution_update` is a distinct provisional local-command output, not a model tool. Saved `bashExecution` command/output now use two selectable text blocks with exit/cancellation, truncation and model-context-exclusion markers, so the projection does not disappear when Pi persists the result.

Lifecycle start/end/settled, message failure/abort, retry attempts, compaction transitions, name/thinking changes, and bounded visible extension notify/status/widget changes use typed journal events. Status/widget keys replace or clear their preceding provisional value. Native session-info, thinking-level and label entries are projected as typed-marker entries; compaction and branch summary entries retain their distinct native entry types and the earlier bounded summary reads. The browser presents relevant signals as provisional status rather than durable conversation messages. `turn_start`, `agent_start`, `turn_end`, `agent_settled`, `entry_appended` are internal lifecycle/activity triggers, not extra text rows. Existing `queue.changed`, question state and command status remain on their previous dedicated paths. RPC acknowledgements, provider/extension hooks, invisible custom entries, extension `setTitle` and editor mutations are not conversation blocks. Unknown native event types yield a type-only fallback; unchecked payloads never cross.

**Privacy and bounds:** live arguments and output can contain credentials. They cross only the authenticated mapped-user journal as UTF-8 text previews limited to 4096 bytes per event, displayed as inert text behind disclosures; the full persisted arguments/results require explicit per-block reads. Images, arbitrary `details`, signatures, extension metadata, provider error strings, retry error strings, raw compaction result objects, and unknown event payloads stay out of live events. Visible extension messages are intentionally user-facing; status/widget updates have replacement/clear semantics rather than a long-lived audit trail. Live events remain transient; Pi's native history is authoritative. A long stream can exceed the bounded tail and then triggers the existing invalidation/recovery path. The prior bounded history limits and redacted-thinking rules still apply.

Browser unit tests check call/result association, history supersession, status replacement/clear and unknown-type fallback; component checks verify readable saved command outcomes and marker labels.
