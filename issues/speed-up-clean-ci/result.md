# Clean gate performance and testing policy

## Current improvement: explicit fast web feedback

`./scripts/test-web-fast.sh` runs the existing formatting, lint, TypeScript, unit and component checks as one command on an installed checkout, without reinstalling dependencies or launching the serial browser suite. No implicit path-based test selection or cached pass is claimed. A developer chooses browser specs when a UI/host journey changes, and the complete clean gate still checks the final runtime/test/release tree. See root `TESTING.md` for the boundary rules.

Measured on this worktree (Linux, Node 22.23.2, warm `web/node_modules`; `/usr/bin/time`, one observation each under variable load): `npm ci --prefix web --no-audit --no-fund` took 3.10 s once. The five checks run individually took 0.15, 0.17, 0.36, 1.90 and 3.34 s wall respectively (5.92 s sum); the new script took **5.98 s** wall, 26.52 s user + 2.84 s system CPU. Thus the wrapper itself does not speed up the same checks. On the current candidate the complete warm-cache clean gate took **293.26 s** (131.81 s user + 28.93 s system CPU), with phases setup 6 s, dependencies 14 s, web checks/build 7 s, serial browser 242 s, Go/contracts/docs 15 s, packaging 9 s and final checks <1 s. The gate passed 84 main browser and 8 lab browser cases. Choosing the 5.98 s fast checks for a pure-client edit gives useful feedback roughly **287 s before** a full run on this host, but it is not equivalent coverage or a faster full gate. The fast command was measured on the same worktree before the gate; the separate runs have different cache and machine load, so this is illustrative, not a controlled speedup claim. The historical warm gate at `d818b51` (183.56 s, 59 browser cases) is not comparable to today's 92 browser cases. These fast checks cannot establish host-backed behavior, UID isolation, contracts, reproducible packaging, or a releasable tree. For browser-facing edits, add the relevant synthetic Playwright journey; for shared or cross-layer changes prefer the full suite. No browser workers were added.

Implementation commit: `b317851` (parent `35dccfc`). The root `TESTING.md` is the single test-selection guide. A runtime/release/test change still runs the complete clean gate once on the final committed tree; documentation-only work uses focused validators. The full gate continues to run the same Go, web, contracts, fixture, license, issue and archive checks. Playwright's E2E and a11y cases now share one host startup and one fresh production build, also used by packaging; standalone browser commands still build their own assets. Go/npm content-addressed caches persist only inside this checkout's ignored `.cache/ci-local/`, while HOME, venv and tool installs remain per-run and disposable.

First new gate phases: setup 5 s, dependencies 21 s, web checks and production build 6 s, browser 132 s, Storybook + Go/contracts/docs 37 s, packaging 9 s, final checks <1 s. The 132-second serial browser suite dominates; it shares a process-wide synthetic scenario switch and cannot safely be parallelized by increasing Playwright workers. On the second new pass, phases were setup 8 s, dependencies 15 s, web checks/build 7 s, browser 130 s, Storybook + Go/contracts/docs 15 s, packaging 9 s. With browser cached on both sides, the old gate took 215 s and the new warm-cache gate 184 s: about 31 s (14%) less wall time on this host. Most of the gain is in Go/build dependency reuse, not the still-dominant serial browser suite. The old 243 s and new 210 s *first* totals are not directly comparable because Chromium cache state differed. These are single observations under variable machine load, not a controlled benchmark; no claim that every run is 14% faster.
